# Sprint 7 実装プロンプト

## 背景

Sprint 1-6 で構築した都市ステータス・食料値・人口・満足度・建物効率・戦闘連動のシステムを、**初期デッキの段階から成立させる** よう再設計する。

具体的には：
- 初期デッキに食堂（DINER）を追加し、序盤から食料値生成が可能にする
- 序盤カードプールに製粉所（MILL）を追加し、報酬で小麦ブーストを得られるようにする
- 住宅・交換所・広場・特殊建物の追加（設計書 §11 に従う）
- 土地カード報酬の実装（既存パネルを上書き改造する報酬カード）

これにより「小麦 → 食堂 → 食料値 → 人口」の導線が初期デッキで成立する。

## 実装対象

### 1. 初期デッキ構成（合計6枚）

設計書 §11 に従う：

| カード | building_type | 枚数 | 役割 |
|---|---|---:|---|
| 森小屋 | SAWMILL | 1 | 木 / 樹脂の獲得 |
| 採掘所 | MINE | 1 | 石 / 鉄鉱石の獲得 |
| 農村 | VILLAGE | 2 | 小麦 / 綿花の獲得 |
| 食堂 | DINER | 1 | 小麦を食料値に変換 |
| 住宅 | HOUSE | 1 | 人口上限の増加 |

修正対象：
- `data/cards_econ.json`：初期デッキ／プール区分のフィールド追加
- `scripts/econ_mvp/EconMain.gd` または `scripts/econ_mvp/EconDeckManager.gd`
  - 初期デッキ構築ロジック（`_build_initial_deck()` 等）の修正
  - `INITIAL_DECK` を定数化

### 2. 序盤カードプール（draw_type: BASIC）

- 製粉所（MILL）を序盤プールに追加
- 既存の SAWMILL/MINE/VILLAGE/HOUSE/DINER も序盤プールに含める
- カード報酬で取得可能にする

### 3. 住宅・交換所・広場・特殊建物の追加（必要分）

要件定義書に記載の追加建物を `EconBuilding.gd` の `BuildingType` enum・`BUILD_COSTS`・`BUILD_HP` に追加し、`update()` 内 match に分岐を追加する。
（住宅(HOUSE) は既存の場合は新規追加不要。要件定義書で確認すること）

### 4. 土地カード報酬

設計書 §（土地カード報酬関連）と要件定義書 §に従う：

- 土地カード報酬として3つの候補がUIに表示される
- 4タイプの候補が確率的に生成される
  - 高数値単一資源パネル
  - 高総量複合資源パネル
  - 香辛料タグ付きパネル
  - 地形指定パネル
- ユーザーが1枚選択できる（UIは暫定でもよい）
- `get_all_overwritable_cells_for_land() -> Array` 新規追加：
  - `land_panels.keys()` から自拠点を除いた配列を返す
- `place_land_card(card, target_pos)` 新規追加：
  - 既存パネルを上書きする（resources/special_tag/terrain_type/category を更新）
  - pos と distance_band は対象座標の既存値を維持
  - 上書き後、食堂・製粉所など土地パネル参照API が上書き後の値を参照できる
- 自拠点パネル（`pos == BASE_INITIAL_POS`）は上書き対象外
- 4タイプの候補生成確率は MVP では均等でよい
- ログ：`[EconGrid] 土地カード上書き` を出力
- 初期デッキに土地カードは含めない（既存6枚は維持）

### 5. 既存初期デッキロジックの完全置換

- 既存の初期デッキ構築ロジックを完全置換する。並存させない
- 旧式が残らないよう grep で確認する

## 制約・注意事項

- 既存の初期デッキ構築ロジックを完全置換する。並存させない
- カード名（製材所／採石場／農場）の呼称統一は本Sprint対象外
- 樹脂・鉄鉱石・綿花の生産はMVP範囲外。森小屋・採掘所・農村は既存の単一資源生産のままでよい
- 製粉所は Sprint 2 で cards_econ.json に追加済み。本Sprintでは「初期デッキに入れない」ことを明確化
- INITIAL_DECK は定数化することで、後の調整・テストが容易になる
- 自拠点パネル（`pos == BASE_INITIAL_POS`）は上書き対象外
- MVP では建物配置済みパネルの上書きも許可
- 4タイプの候補生成確率は MVP では均等でよい
- 土地カード報酬の発生タイミング詳細はCEO/Plannerに委ねる（本要件は「報酬発生時の挙動」を定義）
- land_panels は 26×13 盤面の基礎データを保持する SSoT。土地カードは既存パネルを改造するカードであり、新規パネルを追加しない
