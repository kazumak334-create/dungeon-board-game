# Econ MVP ローグライト構造 要件定義書

STATUS: Draft
更新日: 2026-04-30

---

## 1. 概要

1ラン3戦のローグライト構造と、戦間フェーズ（RestScreen拡張）のメタ進行システム。
戦闘中に蓄積した資源を交易品経由でゴールド（G）に変換し、装備・施設強化でラン中のユニット強化を行う。

---

## 2. 全体構造

### 2.1 ラン構成

| 項目 | 内容 |
|------|------|
| 1ランの戦闘数 | 3戦固定 |
| マップ | 戦闘ごとに切り替え（異なるマップ） |
| 失敗条件 | BASE破壊で即ラン終了 |
| 成功条件 | 3戦クリア |

### 2.2 メタ通貨 G（ゴールド）

| 項目 | 内容 |
|------|------|
| 持ち越し | ランをまたいで永続保持（永続メタ通貨） |
| 使用タイミング | 戦間フェーズ（RestScreen）のショップ3タブ |

### 2.3 資源の扱い

- 通常資源（Wood / Stone / Sulfur / Wheat）は戦間開始時にリセット
- 戦闘中の資源を次戦に持ち越すことはできない
- 資源は交易所タブでGに変換してから持ち越す（変換後のGは永続）

---

## 3. 戦間フェーズ（RestScreen 拡張）

戦闘終了後に表示するRestScreenを3タブ構成に拡張する。

### 3.1 タブ構成

| タブ番号 | タブ名 | 英語名 | 機能概要 |
|---------|--------|--------|---------|
| タブ1 | 交易所 | Trading Post | 資源 → 交易品 → G に変換 |
| タブ2 | 装備屋 | Armory | G でユニット種別バフを購入 |
| タブ3 | 施設強化 | Workshop | G で施設をLvアップ |

---

## 4. タブ1：交易所（Trading Post）

### 4.1 交換ルール

| 交換パターン | 条件 | 生成物 |
|-------------|------|--------|
| 通常単一変換 | 単一資源 × 10個 | 交易品 1個 |
| 複合変換 | Wood/Stone/Sulfur/Wheat × 各5個（計20個） | 複合交易品 1個（高価） |
| レア資源変換 | レア資源 1個（単体） | G に直接変換 |

- 通常資源の単体G直接交換は不可（交易品経由が必須）
- 複合交易品はレート優遇（通常交易品より高いG換算）

### 4.2 デザイン意図

- 単体で捨て売りできない制約により、序盤から交易を戦略に組み込む動機付けをする
- 複数資源を均等に確保する行動を促進する

### 4.3 データ構造

```gdscript
# 交易品データ
{
    "type": "trade_item",          # "normal" | "composite" | "rare"
    "input_resources": Dictionary,  # { "wood": 10 } or { "wood": 5, "stone": 5, ... }
    "output_gold": int,            # G換算値（未確定・保留事項参照）
    "display_name": String         # "交易品" | "複合交易品"
}
```

### 4.4 処理フロー

1. 現在の資源量を表示
2. 交換パターンの選択肢を列挙（条件を満たすもののみ表示）
3. プレイヤーが交換を実行
4. 資源を消費し交易品を生成
5. 交易品 → Gに変換（自動 or 別ステップ、MVP1で確定）
6. 戦間終了時に残資源をリセット

---

## 5. タブ2：装備屋（Armory）

### 5.1 基本仕様

| 項目 | 内容 |
|------|------|
| 購入通貨 | G |
| 効果対象 | ユニット種別（Attacker全員 / Defender全員 等） |
| 個別装着 | なし（種別全員に適用） |
| 有効期間 | ラン中のみ（永続メタ強化ではない） |

### 5.2 装備例（MVP1 確定予定 2種）

| 装備名 | 効果 | 対象 | 価格 |
|--------|------|------|------|
| Attacker強化 | ATK +20% | Attacker全員 | 5G |
| Defender強化 | HP +30% | Defender全員 | 5G |

※具体的なラインナップはMVP1実装時に確定（保留事項参照）

### 5.3 データ構造

```gdscript
# 装備データ
{
    "equipment_id": String,     # 一意ID
    "display_name": String,     # 表示名
    "target_type": String,      # "attacker" | "defender" | "support" 等
    "effect_type": String,      # "atk_percent" | "hp_percent"
    "effect_value": float,      # 倍率（0.2 = +20%）
    "price": int,               # G
    "purchased": bool           # 購入済みフラグ
}
```

### 5.4 処理フロー

1. 購入可能な装備一覧を表示
2. Gが不足する場合は購入不可（視覚的に明示）
3. 購入 → G減算 → 装備をラン中バフとして登録
4. 該当ユニット種別のパラメータに乗算適用

---

## 6. タブ3：施設強化（Workshop）

### 6.1 基本仕様

| 項目 | 内容 |
|------|------|
| 購入通貨 | G |
| 強化対象 | Barracks / Fortress / Workshop / Village |
| 有効期間 | ラン中のみ |
| Lvキャップ | Lv3 |

### 6.2 強化レベル定義

| レベル | 効果 | 価格 |
|--------|------|------|
| Lv1（初期） | 基本値 | - |
| Lv2 | 数値アップ | 8G |
| Lv3 | シナジー効果追加 | 15G（Lv2→3） |

### 6.3 データ構造

```gdscript
# 施設データ
{
    "building_id": String,       # "barracks" | "fortress" | "workshop" | "village"
    "display_name": String,      # "兵舎" 等
    "current_level": int,        # 1〜3
    "max_level": int,            # 3
    "upgrade_cost": Dictionary,  # { 2: 8, 3: 15 }
    "level_effects": Dictionary  # { 2: "...", 3: "..." }（テキスト説明）
}
```

### 6.4 処理フロー

1. 施設一覧と現在Lvを表示
2. 次のLvへの強化コストを表示
3. 購入 → G減算 → current_level += 1
4. Lv3の場合は「強化済」として選択不可表示

## 7. MVP優先度

### MVP1（最初に実装）
- 交易所：交易品作成 + G変換
- 装備屋：Common装備 2種のみ

### MVP2（MVP1完了後）
- Workshop：Lv2強化のみ（Lv1→Lv2）

### MVP3（後回し）
- レア資源・贈り物システム
- Workshop Lv3（シナジー効果追加）
- 装備屋の追加ラインナップ

## 9. 制約・注意事項

### 9.1 既存コードとの整合性

- EconEconomy.gdの資源管理（Wood/Stone/Sulfur/Wheat）をそのまま参照する
- メタ通貨Gは既存のgoldフィールドとは別フィールドとして管理する（混同禁止）
- 戦間リセット処理はEconEconomy.gdのメソッド経由で行う（直接フィールド操作禁止）

### 9.2 GAME_DESIGN.mdとの整合性

- 「限られた資源の流し先を決める」核体験に沿っている（資源配分 → G変換 → 強化選択）
- バトル中操作なし（完全オートバトル）は維持する

### 9.3 KISS原則

- タブUIは最もシンプルな実装から始める（テキストベース → 後でアイコン追加）
- 装備効果は乗算のみ（加算との混在禁止）
- 施設シナジー効果のテキストはMVP1では未実装でよい
