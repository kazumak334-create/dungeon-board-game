## 1. 画面の目的

### 1.1 この画面で何を達成するか

Sprint 8 の主目的は、5分程度のテストプレイで以下を**プレイヤーが3秒以内に判断**できるようにすること。

```text
- 建物が「建っている / 建設中 / 稼働中 / 停止中」のどれか
- 都市の生命線（人口・食料値・満足度・兵力）がどう推移しているか
- 建設キューの現在順番と、各建設の進行/停止状態
- 詰まり要因（資源不足・人手不足）がどこにあるか
```

### 1.2 ユーザーが何を判断・選択するか

| 判断軸 | プレイヤーの選択 | 使うUI |
|---|---|---|
| 都市状態の把握 | 介入が必要か継続観戦かを決める | 常時表示UI（HEADER） |
| 建設順制御 | どの建物を先に完成させるか | 建設キューUI（左側）の順序入れ替え |
| 緊急介入 | Gで即時建設するか、キャンセルするか | 建設キュー項目クリック/右クリック |
| 詳細確認 | 停止理由・効果・足元土地の調査 | 小型ポップアップ（タップ位置） |

### 1.3 核となる体験との整合確認

> 「盤面を設計して、介入を仕込んで、答え合わせを観戦する」

- **盤面設計の延長**: 建設キュー順制御は「設計の続き」（バトル開始後も介入可能）
- **介入の仕込み**: 即時建設G・建設キャンセル・人手再配分が「介入」
- **観戦**: BPB式進捗Overlay/Mask が「答え合わせを見守る」体験を担保
- 詳細ポップアップを**右側パネル/ボトムシートにしない**ことで、盤面（観戦対象）の視認性を最優先

### 1.4 KISS原則の遵守

- 新規色定義は **0個**（既存 `COLOR_*` のみ）
- 詳細表示は **小型ポップアップ1種**（右側パネル・ボトムシート禁止）
- 停止理由は **アイコン+❌のみ**（テキストは詳細ポップアップに格納）
- 建設中ポップアップは作らない（建設キュー＋盤面表示で十分と判断）
- 人手詳細ポップアップを新規追加しない（既存スライダーを継続使用）

#### レイアウト計算（5項目をスクロールなしで表示できるか）

```
キュー領域高さ: 420px (y=100-520)
内訳:
  - ヘッダー "BUILD QUEUE": 24px
  - 内側パディング上下: 8px × 2 = 16px
  - 項目高さ: 56px × 5 = 280px
  - 項目間マージン: 4px × 4 = 16px
  - 合計: 24 + 16 + 280 + 16 = 336px

実効使用: 336px / 確保420px → 余裕 84px
→ 5項目はスクロールなしで余裕を持って収まる
→ 6項目以上はスクロールバーを表示（マスクで枠内クリップ）
```

#### 余白方針（ギチギチを避ける）

| 余白箇所 | サイズ | 目的 |
|---|---|---|
| HEADER下端 → キュー/盤面上端 | 20px (y=80-100) | HEADER数値群とプレイ領域を視覚的に分離 |
| キュー/盤面下端 → FOOTER上端 | 20px (y=520-540) | プレイ領域とFOOTERコントロール群を分離 |
| キュー外枠 → 項目 | 内側上下8px | 枠と内容のはみ出し感を防ぐ |
| 項目同士 | 上下4px | 個別項目の独立感を担保 |
| キュー左端 | x=0 起点 | 画面左端に密着させ盤面領域を最大化 |
| キュー右端 → 盤面左端 | 12-16px（盤面側調整） | キューと盤面の視覚的分離 |

> **判断**: HEADER/FOOTERとの間に20pxずつ確保することで、ギチギチに詰まった印象を回避し、視線がHEADER→キュー/盤面→FOOTERと滑らかに流れる。これは「世界観の匂わせ＝整いすぎている」を担保する空間制御でもある。

### 2.3 視線の流れ

```
通常時の視線流れ:
  HEADER（都市状態確認）
    ↓
  BOARD（建物の建設状況・稼働状況を観戦）
    ↓
  建設キュー（左側）で次の優先順位を見直す
    ↓
  FOOTER（人手スライダー・手札）で介入

詳細確認時の視線流れ:
  HEADERや盤面の対象をクリック
    ↓
  クリック位置の近傍に小型ポップアップ出現
    ↓
  詳細を読み、別箇所クリックで閉じる/切り替え
```

> **判断**: 建設キューを盤面**左側**に配置する理由は、(1) 視線がHEADER→BOARDに自然に流れた後、左に視線を移して優先順位を確認できる動線を作るため、(2) 右側（手札）と物理的に分離することで「キューは過去の決定（並び替え対象）/ 手札は次の決定（カード使用）」を空間的に区別するため。

#### BPB式進捗の視覚化（建設キュー版）

```
進捗0% → 1% → 50% → 99% → 100%
┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐
│① 住宅 │  │① 住宅 │  │① 住宅 │  │① 住宅 │  │      ✓ │  ← 完成消滅
│        │  │        │  │        │  │▓▓▓▓▓▓ │  │ (1フレ │
│        │  │        │  │▓▓▓▓▓▓ │  │▓▓▓▓▓▓ │  │  発光) │
│        │  │▓▓     │  │▓▓▓▓▓▓ │  │▓▓▓▓▓▓ │  │        │
│ G:60   │  │ G:59   │  │ G:30   │  │ G:1    │  │        │
└────────┘  └────────┘  └────────┘  └────────┘  └────────┘
        ↑ 下から金色（COLOR_ACCENT_GOLD α=0.4）が塗り上がる
        ↑ 項目背景全体（番号・名称・コスト行を除く中央領域）に重ねる
        ↑ 完成時は200ms全面発光 → キューから消滅・後続が繰り上がる
```

| 進捗状態 | Overlay表現 |
|---|---|
| 0%（開始前） | Overlay非表示。項目背景は COLOR_PANEL のまま |
| 1-99%（進行中） | 下から上へ進捗率分の高さで COLOR_ACCENT_GOLD α=0.4 を塗る |
| 100%（完成瞬間） | 全体を COLOR_ACCENT_GOLD α=0.6 で200ms 発光、その後キューから消滅 |
| 停止中 | Overlayを COLOR_TEXT_DIM α=0.3 で塗る（高さは保持・進捗は止まる） |

> **判断**:
> - 線形バーから BPB式（下→上塗り）に変更する理由は、(1) 完成済み稼働建物のBPB式効果Overlay（§4.4）と「同じ進捗表現言語」を使い、視覚的学習コストを統一するため、(2) 線形バー1行分（12px）を削減して項目高さを 64px→56px に縮められるため、(3) 「下から積み上がる」動きは「建てている」物理的メタファーと一致するため
> - 項目背景が塗り上がる方式により、進捗が一目で「項目内のどの高さまで来たか」で把握できる（細い線形バーよりも視認性が高い）

#### 操作

| 操作 | 動作 |
|---|---|
| キュー項目クリック | 確認なしでGを消費して即時建設（建設進捗100%） |

> - キュー項目クリック=即時建設は、確認ダイアログを挟まず、Gが足りなければ赤フラッシュで拒否
> - ドラッグでの順番入れ替えはGodot標準のDrag&Drop機構を流用
> - 即時建設コスト「G:60」は通常時は3行目に表示（停止中は停止理由を優先表示）
> - スクロールバーは標準の細いゲージで右端に表示（5項目以下では非表示）

### 4.2.1 即時建設コストの計算方法

> **改訂（2026-05-04）**: コスト計算を「残り建設時間 × 10G」から「工数単価 × 残工数」方式に変更（要件定義書 `REQUIREMENTS_SPRINT_8.md` と整合）。

#### 計算式

```
即時建設コスト G = 工数単価 × 残工数

ここで:
  工数単価     = 5G/工数（全建物共通）
  総工数       = 建物固有の値（Sprint 7 construction_time から導出）
  残工数       = 総工数 × (1 - 進捗率)
  進捗率       = 建設進行度（0.0〜1.0）
```

#### 設計意図

| 項目 | 旧方式（時間×10G） | 新方式（工数単価×残工数） |
|---|---|---|
| コスト基準 | 時間（秒） | 工数（人時） |
| 全建物共通単価 | 10G/秒 | **5G/工数** |
| 建物固有値 | construction_time（秒） | **総工数（construction_time から定数倍で導出）** |
| 残コスト計算 | 残時間 × 10G | **残工数 × 5G** |
| 利点 | 直感的（時間経過＝コスト減） | 「人手で建てている」感覚と整合・建物規模で差別化しやすい |

#### 具体例

```
例1: 住宅（総工数12、進捗0%）
  残工数 = 12 × (1 - 0.0) = 12
  即時建設コスト = 5G × 12 = 60G

例2: 住宅（総工数12、進捗50%）
  残工数 = 12 × (1 - 0.5) = 6
  即時建設コスト = 5G × 6 = 30G

例3: 兵舎（総工数40、進捗0%）
  残工数 = 40 × (1 - 0.0) = 40
  即時建設コスト = 5G × 40 = 200G

例4: 兵舎（総工数40、進捗75%）
  残工数 = 40 × (1 - 0.75) = 10
  即時建設コスト = 5G × 10 = 50G

例5: 食堂（総工数16、進捗25%、停止中）
  残工数 = 16 × (1 - 0.25) = 12
  即時建設コスト = 5G × 12 = 60G
  （停止中でも進捗率が保持されているため計算可能）
```

#### UI表示

- キュー項目の3行目に「G:60」形式で表示（11px Regular、COLOR_GOLD_COIN）
- 進捗が進むと数値がリアルタイム更新（毎フレーム再計算）
- ホバー時は強調表示（COLOR_GOLD_COIN α=1.0、通常時は α=0.85）
- Gが不足している場合は数値を COLOR_RED で表示
- 停止中の場合はコスト表示を隠し、停止理由アイコンを優先表示

> **判断**:
> - 工数単価は全建物共通で5G固定とすることで、プレイヤーが「残工数 × 5 = 必要G」を暗算で把握できる（学習コストを最小化）
> - 建物固有の総工数は construction_time（Sprint 7）から導出する。具体的な変換係数は Architect が要件定義書で確定する
> - 停止中でも進捗率は保持されるため、計算式は停止/稼働を問わず一貫して動作する

### 4.4 BPB式 効果進捗Overlay（共通建物進捗UI）

完成済み稼働建物アイコン上に、進捗率に応じて「下から上へ伸びるハイライト」を重ねる。

```
建物パネル（稼働中・進捗 60%）:
┌───────────┐
│           │
│ [建物    ]│  ← 通常建物Sprite（不透明）
│ [アイコン]│
│ ░░░░░░░░░│  ← 進捗Overlay (高さ60% を下から塗る、COLOR_ACCENT_GOLD α=0.4)
│ ▓▓▓▓▓▓▓▓│
└───────────┘

進捗 100% 到達時:
全体ハイライト → 200ms 発光 → progress_rate=0 にリセット
```

| 進捗率 | Overlay表現 |
|---|---|
| 0% | Overlay非表示（建物アイコンのみ） |
| 1-99% | 下から上へ進捗率分の高さで COLOR_ACCENT_GOLD α=0.4 を塗る |
| 100%（発動瞬間） | 全体を COLOR_ACCENT_GOLD α=0.6 で200ms 発光、その後0%へ戻る |
| 停止中 | Overlayを COLOR_TEXT_DIM α=0.3 で塗る（高さは保持） |

実装方針：
- `_draw()` で `draw_rect()` に `Rect2(0, h*(1-rate), w, h*rate)` を渡す
- progress_rate は 0.0〜1.0 で管理（既存EconBuilding側で進行）
- 周期発動建物・累計条件型建物・条件進捗型建物すべて共通仕様

> **判断**: BPB式（下→上ハイライト）は Sprint 7 の建設リングゲージ（円弧）と**形状が異なる**ため、建設進捗と建物効果進捗を視覚的に混同しない。リング=建設、塗りつぶし=効果発動、と形状で区別する。

## 6. UI基準チェック

### 6.1 6項目評価

| # | 基準 | 評価 | 根拠 |
|---|---|---|---|
| 1 | **3秒ルール** | ◎ | 建物の状態（建設中=リング/稼働中=塗りOverlay/停止中=❌アイコン）が形状で識別可能。HEADER常時表示で都市状態が瞬時把握可能 |

| 「どの建物が稼働して何を生産しているか」 | ◯ | BPB式Overlayで進捗は分かるが、効果内容は詳細ポップアップが必要 |
| 「プレイヤーが何を判断しようとしているか」 | ◎ | ポップアップ表示位置でプレイヤーの注目箇所が明確 |

### 6.3 世界観の匂わせ検証

「ダークファンタジーに見えるが、どこか無機質で整いすぎている」

- **整いすぎ要素**: HEADER数値の整列・キュー番号の機械的採番（1,2,3...）・進捗バーの幾何学的形状
- **ダークファンタジー要素**: 暗い背景・金色アクセント・装飾枠の単純さ・BPB式Overlayが「儀式の進行」を匂わせる
- **説明しない**: ツールチップは詳細ポップアップ内のみ、HEADER項目に説明テキストなし、デバッグツール以外は装飾も最小

### 7.1 Designer視点の残論点（要件定義フェーズで確定）

| 項目 | 残論点 | 推奨判断 |

| 効果Overlay進行方向 | 下→上 vs 円形 vs 横バー | **下→上**を推奨（BPB踏襲・建設リング=円との形状区別） |

| デバッグログオーバーレイ位置 | 画面右上 vs 画面下 vs 別ウィンドウ | **画面右上 320×200**を推奨（盤面視認性確保・デフォルトOFF） |

### 7.3 要件定義書に渡す確定事項リスト

Architect が要件定義書を起こす際の **Designer承認済み事項**:

1. **新規UI座標・サイズ**:
   - 建設キューUI: 140 × 420、x=0, y=100-520（HEADER下20px・FOOTER上20pxの余白を確保）
   - キュー項目: 高さ56px、5項目までスクロールなし表示・6個目以降スクロール
   - キュー進捗表現: BPB式（下→上塗り、項目背景全体に重ねる）
   - HEADER上段（都市状態）: 1280 × 36、既存HEADER内に統合
   - 建設順番号バッジ: 直径18px、建設予定地パネル左上
   - BPB式効果進捗Overlay: パネルサイズ全域（下→上塗り）
   - 停止理由アイコン: 16×16、建物パネル右上 / キュー項目内
   - 小型ポップアップ: 240px幅 × 可変高（最大280px）
   - デバッグツールパネル: 320 × 180、FOOTER右端

2. **使用する色定数**:
   - 既存EconMain.gd の `COLOR_*` 定数のみ
   - 新規色定義は **追加しない**

3. **アニメーション仕様**:
   - ポップアップ出現: 80ms ease-out
   - 効果発動発光: 200ms ease-in-out
   - 即時建設成功フラッシュ: 300ms ease-out
   - 建設キャンセル: 200ms ease-in
   - キュー項目ホバー: 100ms 線形

4. **インタラクション**:
   - 詳細表示: 1クリック（HEADER項目 / 盤面建物）
   - 即時建設: 1クリック（キュー項目）
   - 建設キャンセル: 1右クリック（キュー項目）
   - 順序入れ替え: ドラッグ（10px閾値）
   - ポップアップ閉じる: 外部空白クリック
   - ポップアップ切り替え: 別対象クリックで即時切り替え（中間状態なし）

5. **状態の可視化ルール**:
   - 建設中（進行）: 半透明シルエット + 金色リング + 番号バッジ（Sprint 7継承）
   - 建設中（停止）: 上記 + 灰色リング + キュー側❌アイコン
   - 稼働中（進行）: 通常パネル + BPB式下→上塗りOverlay
   - 稼働中（停止）: パネル α=0.7 + 灰色Overlay + ❌アイコン
   - 効果発動: 200ms金色全面発光 → 0%リセット

6. **ポップアップ統一方針**:
   - 3種（満足度・兵力・建物）すべて同一パネル形式
   - 出現位置: クリック座標+12px、画面外補正あり
   - 建設中ポップアップは作らない
   - 人手詳細ポップアップは作らない（Sprint 7既存スライダーを継続使用）
   - 右側パネル・ボトムシートは禁止

7. **ログ・デバッグ方針**:
   - ログ種別: 人口・食料値・満足度・建物稼働・建築・人手・資源獲得・兵力/兵数/ユニット・防衛突破
   - ログ形式: テキスト1行（タイムスタンプ + key=value）
   - ログ表示: デフォルトOFF・デバッグONで画面右上オーバーレイ
   - デバッグツール: 開発時フラグで表示・本番ビルドでは非表示

8. **即時建設コスト計算（2026-05-04 改訂）**:
   - 計算式: `工数単価 × 残工数`
   - 工数単価: 5G/工数（全建物共通）
   - 総工数: 建物固有値（Sprint 7 construction_time から導出・係数はArchitectが要件定義書で確定）
   - 残工数: `総工数 × (1 - 進捗率)`
   - 表示: キュー項目3行目に「G:60」形式（COLOR_GOLD_COIN）
   - G不足時: 数値をCOLOR_REDで表示・クリック時は赤フラッシュで拒否
   - 停止中: コスト表示を隠し停止理由アイコンを優先

9. **キュー進捗表現（2026-05-04 改訂）**:
   - 線形バーを廃止し、項目背景全体に **BPB式（下→上塗り）** を適用
   - 進行中: COLOR_ACCENT_GOLD α=0.4 で進捗率分の高さを下から塗る
   - 停止中: COLOR_TEXT_DIM α=0.3 で塗る（進捗高さは保持）
   - 完成瞬間: 200ms 全面発光（α=0.6）→ キューから消滅
   - これにより建物パネル上のBPB式効果Overlay（§4.4）と進捗表現言語を統一
