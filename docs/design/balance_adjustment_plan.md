- ユニット18体のバランス調整は別作業（Phase 4 #11と並行）
- 本計画では**ユニット以外の全調整要素**を抜け漏れなく扱う

**参照設計文書**

## Sprint A: 呪文カードバランス

### 目的
全呪文カード（player_spells, spells, system_spells, status_spells）のコスト・効果値・レアリティ適正を調整。

### 対象ファイル
- data/cards.json（"spells", "system_spells", "status_spells"セクション）

### 調整項目

| 項目 | 調整内容 | 判断基準 |
|-----|---------|---------|
| コスト | 1-6の範囲で再調整 | マナ経済（初期3、上限3、回復量1）に対する適正 |
| 効果値 | ダメージ・バフ・デバフ量 | ユニットHP/ATK平均値との相対比較 |
| レアリティ | common/uncommon/rare/epic/legend | 効果範囲・条件・数値で階層化 |

### 実装手順

1. **現状分析**
   - 全呪文のコスト・効果値・レアリティを一覧化
   - マナ経済（初期3/上限3/回復1）での使用頻度を試算
   - レアリティ別効果範囲の適正チェック

2. **調整方針決定**
   - コスト1-2: 単体・小効果（common）
   - コスト3: 複数体・中効果（uncommon）
   - コスト4-5: 全体・大効果（rare/epic）
   - コスト6: ゲームチェンジャー（legend）

3. **データ修正**
   - data/cards.json の該当フィールド変更
   - mana/effect/rarity フィールド

4. **検証**
   - バトル実行テスト（各レアリティ1種以上使用）
   - マナ枯渇・余剰状況の確認
   - レアリティ別価値感の妥当性チェック

### 完了定義
- 全呪文のコスト・効果値・レアリティが調整済み
- バトルテスト3回実施（初期/中期/後期想定）
- roadmap.md Phase 4 #11 備考欄に「Sprint A完了」記載

### 目的

### 対象ファイル
- data/cards.json（"relics"セクション）

### 調整項目

| 項目 | 調整内容 | 判断基準 |
|-----|---------|---------|
| 効果値 | HP/ATK/SPDバフ量、マナ増加量 | ユニット基礎値の10-30%を基準 |
| 希少度 | common/uncommon/event | 効果範囲・数値で階層化 |
| 発動条件 | battle_start/always/timed | 戦略的価値と希少度の対応 |

### 実装手順

1. **現状分析**
   - 実装済み7種レリックの効果値一覧化
   - ユニット平均HP/ATK/SPD算出（18体の平均）
   - レリック効果の相対比較

2. **調整方針決定**
   - common: 単一ステータス+2〜5
   - uncommon: 複数ユニット対象、条件付き強効果
   - event: フレーバー重視（効果なし or 特殊効果）

3. **データ修正**

4. **検証**

## Sprint C: マナ経済バランス

### 目的
マナ初期値・上限・回復量・クラス特性のバランス調整。

### 対象ファイル
- data/cards.json（"classes"セクション: initial_mana, mana_max, mana_regen）
- scripts/GameSession.gd（DEFAULT_BATTLE_CONFIG: mana_regen_rate）

### 調整項目

| 項目 | 調整内容 | 判断基準 |
|-----|---------|---------|
| 初期マナ | クラス別差異化 | 呪文コスト平均値との兼ね合い |
| マナ上限 | クラス別差異化 | 高コスト呪文使用可否 |
| 回復量 | 1.0倍率の妥当性 | ユニット生成マナ（Cost依存）とのバランス |
| クラス特性 | skills配列での補正 | 錬金/バーサーカー/死霊の差別化 |

### 実装手順

1. **現状分析**
   - 3クラスのマナ初期値・上限・回復量を一覧化
   - 呪文コスト平均値算出
   - バトル中マナ枯渇・余剰状況のシミュレーション

2. **調整方針決定**
   - 全クラス共通: initial_mana=3, mana_max=3, mana_regen=1（現状維持 or 差異化）
   - クラス特性でマナ経済に差をつける（例: 錬金術師は合成時マナ+2、死霊術師はマナ上限+1等）

3. **データ修正**
   - data/cards.json の "classes" セクション
   - scripts/GameSession.gd（必要に応じてmana_regen_rate調整）

4. **検証**
   - 3クラス×3バトル（初期/中期/後期想定）でマナ経済テスト
   - マナ枯渇・余剰・クラス差の確認

### 完了定義
- 3クラスのマナ経済が調整済み

## Sprint D: 敵デッキ強度バランス

### 目的
Act別・警戒レベル別の敵デッキ（weak/enhanced1/2/3/elite/boss）の強度調整。

### 対象ファイル
- data/cards.json（"enemy_pools", "elite_pools", "boss_decks"セクション）

### 調整項目

| 項目 | 調整内容 | 判断基準 |
|-----|---------|---------|
| weak デッキ | Act1-3 の基準強度 | プレイヤー初期デッキと同等 |
| enhanced1-3 | 警戒Lv3-5の段階的強化 | ユニット構成・列配置の変更 |
| elite_pools | エリート混入時の強敵 | weak+1段階上のユニット |
| boss_decks | 3段階デッキ（通常/強/激昂） | 専用ユニット含む最高難度 |

### 実装手順

1. **現状分析**
   - Act1-3 の各デッキ構成を一覧化
   - ユニットHP/ATK/Cost平均値算出
   - 警戒レベル0-5での強度グラデーション確認

2. **調整方針決定**
   - weak: Cost平均2.0、HP/ATK低め
   - enhanced1: Cost平均2.5、中列配置増加
   - enhanced2: Cost平均3.0、後列配置増加
   - enhanced3: Cost平均3.5、全マス埋め
   - elite: enhanced2相当+高Costユニット1体
   - boss: 専用ユニット含む最強構成

3. **データ修正**
   - data/cards.json の該当デッキ配列
   - name/col フィールド調整

4. **検証**
   - 各デッキでバトルテスト（Act1-3×weak/enhanced1-3/elite/boss = 21回）
   - 難易度曲線の妥当性確認

### 完了定義
- 全敵デッキが調整済み
- バトルテスト21回実施
- roadmap.md Phase 4 #11 備考欄に「Sprint D完了」記載
