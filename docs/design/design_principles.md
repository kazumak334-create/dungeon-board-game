# 設計判断基準

## カード効果設計

### 基本原則
- 差分は「追加」だけでなく「削除」でも作れる。何もないが最善の場合がある
- 全部盛りは雑。コンセプトを1つに絞って、そこから外れる効果は入れない
- 手段と目的は分けて考える。異常状態は手段・突守崩は目的。同じ毒でも目的によって突にも守にもなる
- やること決めることと同じくらい、やらないことを決めることが重要。設計の制約は自由度を下げるのではなく選択の質を上げる

### 強さの判断
- 強さの判断はコンセプトに従って強すぎないかを見る。判断基準は同レアリティとの対比。数値を揃えることが目的ではない
- 効果を混ぜる・強くする・弱くする判断の軸は「プレイヤーの選択肢が増えるか」。純粋なビルドの邪魔になるなら混ぜない

### 3点チェック（毎回自分でやる・言われる前にやる）

**派生内チェック**
- Common→Uncommon→Rare→Epic→Legendで段階的に強化されているか
- 各レアリティで「何が変わるか」が1つ明確になっているか
- 前のレアリティの劣化版になっていないか
- 合格基準：各レアリティを見て「このレアリティでしかできないこと」が言えるか

**同レアリティチェック**
- 同じレアリティの他カードと比べてHP・ATK・SPD・マナ生成が過剰に強くないか
- 効果の強さがコンセプトに見合っているか
- 合格基準：同レアリティで並べたときに突出して強すぎるカードがないか

**コンセプトチェック**
- カードの効果がコンセプトから外れていないか
- 前列能力・サポート効果・特性が同じ方向を向いているか
- 混ぜることでプレイヤーの選択肢が増えるか・純粋なビルドの邪魔になっていないか
- 合格基準：「このカードが何をするカードか」を3秒で言えるか

### 効果の種類と制約
- 前列能力は攻撃時トリガーで発動。特性で付与する効果を前列能力に入れるとバグる
- サポート効果は中列・後列から発動。前列に干渉する効果はサポート効果として成立しないケースがある
- 特性は常時発動パッシブ。サポート効果・前列能力と混同しない
- スタックしないものをサポート効果で実装するのはセンスがない
- 盤面効果・呪文介入はプレイヤー領域。ユニット効果で直接触るのは設計ミス
- 呪文スロットはプレイヤー側のシステム。敵ユニットには存在しない
- キャストゲージ速度上昇はユニットへのバフではなくスキルの領域

## ツリー設計

- 合成ツリーはGod→Legend→Epic→Rareの逆算で設計する
- シナジーを生む関係は必ずしも派生順序と一致しない。同レアリティや異なるルートのカード同士がシナジーを持つ場合、ツリー上の位置関係に縛られずに設計する
- 枝分かれ・合流はカード効果の系統から自然に決まる。先に決める必要はない

## レアリティ設計

- Legend・Godの強さは数値インフレだけでなく突出ポイントを1つ作る
- 各レアリティで役割を1つに絞る。Rare→Epic→Legendで何が変わるかを明確にする
- LegendとGodの差は「条件付きで突出する」vs「条件なしで突出する」
- Godはコンセプトの極致。Legendの劣化版ではなく別の突出ポイントを持つ

## ゲーム設計

- 手段と目的は分けて考える。勝ち筋から派生させてカード型を定義する。型→手段の順で考える
- 問いを立ててから答えを出す。問いが浅いと設計がブレる
- 守の強さはマナ連動で成立している。追加ルール不要
- 崩の定義は「相手の意図を壊す」。前線への干渉は守の領域
- 種族は勝ち筋に縛らない。種族×勝ち筋の2軸で設計する
- 勝ち筋ごとに問いを立てる。突は「誰を・どう・いつ削るか」守は「どう維持し・どう消耗させ・いつか」崩は「何を・どういう状態に・どうやって機能不全にするか」

## レビュー

- 批判的レビューは忖度せず設計の矛盾を指摘する
- ペルソナレビューは感情的反応まで踏み込む。論理だけでは不十分

## 判断の原則

- 課題感に立ち返って判断する。元の課題感に矛盾する提案には理由を持って反論する
- 自明なことを確認しない。スタンスを持って提案し、加藤さんに選択コストをかけない
- 確認が必要なのは「加藤さんにしか分からない意図・好み・方針」のみ
