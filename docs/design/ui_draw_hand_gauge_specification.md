## 1. 設計の前提と判断軸

### 1.1 体験設計の核（企画書からの継承）

「**設計して、介入を仕込んで、答え合わせを観戦する**」核体験のうち、**セミリアルタイム制下の時間圧と配分判断**を可視化する装置である。

| 体験 | UI が担う役割 |
|------|-------------|
| 限られた資源の流し先を決める | 手札・人口・資金・食料で「次の選択肢」を提示 |
| その配分が戦況を作る快感 | 兵力ゲージで「ためている量」が見える |
| 読み違えた悔しさ | 強制突撃ゲージで「もう時間が無い」圧 |
| 観戦＝答え合わせ | HEADER 集約で配信視聴者にも状況伝達 |

### 1.2 KISS と引き算の検証（v0.2 改訂5 ユーザー承認版）

| 削れるか？ | 検証 | 結論 |
|----------|------|------|
| HEADER に集めすぎでは？ | 56px 2段構成で、上段=結果ステータス・下段=材料/時間圧に階層化 | **HEADER 56px 維持・2段構成必須** |
| Idle旗ボタンは必要か | 一斉突撃発動は BASE 長押しに統一できる | **削除**（BASE 長押し0.6秒に統合） |
| START ボタンは常時必要か | 初回開始のみで以降不要 | **初回のみ盤面中央フローティング・以降消滅** |
| EARLY CHARGE ボタンは必要か | 一斉突撃発動は BASE 長押しに統一 | **削除**（BASE 長押しに統合） |
| Drawゲージの位置は HEADER で良いか | 手札の文脈に近接させる方が自然（手札増減＝ドロー） | **FOOTER 手札スクロール右上に移動** |
| AI資源表示は必要か | 配分判断はプレイヤー資源のみ | **削除**（KISS） |
| 初期農村・初期ハーベスター×2 | 開幕状態が複雑・KISS違反 | **削除**（開幕は完全に空）|
| 左側ハーベスター UI を維持できるか | 自動稼働化で割り当て概念が消滅 | **完全削除** |
| BUILD区を維持できるか | 即時消費に変更されたため不要 | **完全削除** |
| 手札 5枚維持で良いか | 13枚デッキ + 書庫追加ドローで保留が頻発する | 不可。**8枚スクロール必須** |
| 満足度を v0.2 で UI に出すか | 体感は無いが拠点・将来繰越の視覚予告必須 | **数値0表示・タイトル"v0.3"明示** |
| デッキ残・捨て札の常時表示 | 13枚デッキでは枯渇危険があり把握必須 | **必須**（コンパクト表示） |
| イベント選択区の v0.2 表示 | 「将来ここに来る」を予約しないと配置を圧迫する | **必須**（ロック状態UI） |

### 1.3 解像度・対象デバイス

- **基準解像度:** 1280×720（既存 EconMain.gd 準拠）
- **HEADER 高さ:** **56px**（v0.1 復帰・2段構成で情報集約）
- **FOOTER 高さ:** **180px**（v0.1 維持）。手札8枚・デッキ/捨て札・イベント選択区を納める
- **盤面（BOARD）:** y=56, h=464（HEADER −24px 分を盤面拡張に充当）
- **モバイル対応:** v0.2 では非対応（PC マウス前提）

### 1.4 色定数（v0.2 改訂2 で追加）

既存 + v0.1 で追加済の色は流用する。v0.2 で新規追加するのは以下4つ。

```gdscript
# EconMain.gd への追加（v0.2 改訂2）
const COLOR_POP       := Color("#5D8FB8")  # 人口ゲージ青系
const COLOR_SAT       := Color("#B89AC7")  # 満足度パープル系（v0.3 本格化）
const COLOR_TROOP     := Color("#B85A3C")  # 兵力ゲージ赤茶（攻撃の予兆）
const COLOR_GOLD_COIN := Color("#E0C060")  # 資金（既存 COLOR_ACCENT_GOLD より明るい・コインの光）
```

**設計判断：**
- 人口/満足度/兵力/資金は**配分判断の4軸**であり、それぞれ専用色を割り当てて視認性を最大化
- ダークファンタジー世界観を保つため、彩度を抑えて既存 #DCD2B9 系のテキストと共存
- 既存 `COLOR_RED` は「危険・上限到達」専用とし、新色とぶつけない

### 3.3 人口表示（POP）

**プレイヤーに感じてほしいこと：「もう建てられない」上限の存在 / 余裕**

| 項目 | 値 |
|------|----|
| 配置 | x=8, y=0, w=130, h=28 |
| アイコン | 人型シルエット 16×16（COLOR_POP） |
| ラベル | "POP" 9px DIM |
| ゲージ | 60×6px ゲージバー |
| 数値 | "現在 / 上限"（例：「12/50」・10px） |

**色分け（比率ベース・v0.2）:**

| 比率 | ゲージ色 | 数値色 |
|------|--------|-------|
| 0〜70%（余裕） | `COLOR_GREEN` (`#3F6932`) | `COLOR_TEXT` |
| 70〜99%（警告） | `COLOR_YELLOW` (`#A9924F`) | `COLOR_TEXT` |
| 100%（満タン） | `COLOR_RED` (`#9C3A2A`) | `COLOR_RED` 太字 |

**初期状態：** 0/50（拠点+50 のみ・住居なし・初期農村も削除済み）→ ゲージ 0% 表示。

**人口不足時の連動表現：**
- 数値の右下に `⚠ N棟停止中` を 8px 赤で表示（停止建物がある時のみ）

### 10.3 初期ユニット配置（削除確認）

#### 10.3.1 削除対象

v0.2 改訂5 では以下の初期ユニット配置を**完全削除**：

- **初期農村 ×1**（v0.1 では BASE 隣接に配置）
- **初期ハーベスター ×2**（v0.1 では BASE 隣接に配置）

#### 10.3.2 削除理由

- 開幕状態を完全に空にすることで、KISS原則と整合
- プレイヤーが「何もない盤面に建てていく」体験を最初から味わえる
- 初期配置の文脈説明が不要になり、初心者の認知負荷が下がる

#### 10.3.3 削除実装方針

- EconMain.gd の `_ready()` で実行されている初期ユニット生成処理を削除
- 関連する初期化フラグ・座標定数（あれば）も削除
- BASE のみが盤面に存在する状態で開始
