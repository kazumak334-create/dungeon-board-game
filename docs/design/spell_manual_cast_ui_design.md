# 呪文手動発動UI/UX企画書

## 1. 画面の目的

### この画面で何を達成するか
- バトル観戦中、プレイヤーが呪文発動の**タイミング**を能動的に判断する。
- 3つの呪文スロットそれぞれについて「今発動すべきか / 今は待つか / 捨てるか」の3択を即断する。

### ユーザーが何を判断・選択するか
- **左クリック**：呪文発動（条件＋マナ満足時のみ有効）
- **右クリック**：スロット破棄（既存機能）
- 「盤面の劣勢タイミング」「味方の集合度」「敵キュー先読み」を踏まえて介入タイミングを決める。

### 核体験との整合性
「盤面を設計して、介入を仕込んで、答え合わせを観戦する」——本UIは**介入フェーズ**の中心。自動発動から手動発動へ切り替えることで、観戦中の意思決定量を増やし、介入の質を高める。

## 2. レイアウト構成

### 2-1. 配置座標（既存GameUI.gdの呪文スロット領域を流用）

```
base_x = CENTER_X - GAP/2 - 3*CELL_W + 10    （自陣盤面の左下）
base_y = BOARD_TOP + 3*CELL_H + 260          （盤面下・キュー下）
slot_w = 90px, slot_h = 130px, slot_gap = 10px
```

3スロット横並び：合計幅 `90*3 + 10*2 = 290px`

### 2-2. 領域分割

```
┌─────────────────────────────────────────────────────┐
│ 呪文スロット（左クリック発動／右クリック破棄）      │ ← タイトル(font 11)
├──────────┬──────────┬──────────┬────────────────────┤
│ Slot 1   │ Slot 2   │ Slot 3   │                    │
│ 90×130   │ 90×130   │ 90×130   │                    │
│          │          │          │                    │
│ [状態]   │ [状態]   │ [状態]   │                    │
│ 呪文名   │ 呪文名   │ 呪文名   │                    │
│ [条件]   │ [条件]   │ [条件]   │                    │
│ コスト:N │ コスト:N │ コスト:N │                    │
│ ▶発動可 │ ×マナ不足│  空き    │                    │
└──────────┴──────────┴──────────┴────────────────────┘
```

### 2-3. 視線の流れ

1. 盤面（上）→ 戦況把握（3秒）
2. 呪文スロット（下）→ 発動判定（1秒：光っているかグレーアウトか）
3. 光っているスロット → 左クリック → 即発動

**Tips**：盤面とスロットは**縦方向に連続配置**されており、視線移動は最小。

## 3. 色彩設計

### 3-1. 色定義（既存MaterialSelect.gd風の命名規則に従う）

```gdscript
# GameUI.gd 既存値と整合
const COLOR_SLOT_EMPTY       = Color(0.08, 0.10, 0.14, 0.8)  # 空きスロット（既存）
const COLOR_SLOT_LOADED_OFF  = Color(0.12, 0.15, 0.22)       # 装填・発動不可（既存流用）
const COLOR_SLOT_READY_BG    = Color(0.18, 0.32, 0.22)       # 発動可能（緑がかった活性色・新規）
const COLOR_SLOT_GLOW        = Color(0.6, 1.0, 0.7, 0.85)    # 発動可能の縁取り発光（新規）
const COLOR_LABEL_READY      = Color(1.0, 1.0, 1.0)          # 発動可能時ラベル
const COLOR_LABEL_DISABLED   = Color(0.5, 0.5, 0.5)          # 発動不可時ラベル
const COLOR_LABEL_EMPTY      = Color(0.5, 0.5, 0.5)          # 空きスロットラベル
const COLOR_READY_ACCENT     = Color(0.4, 1.0, 0.5)          # 「▶ 発動可」テキスト
const COLOR_FAIL_ACCENT      = Color(1.0, 0.35, 0.35)        # 「× 失敗」テキスト・フラッシュ
```

### 3-2. 既存画面との統一感

- **MaterialSelect.gd / DeckPrep**：パネル色 `Color(0.08, 0.10, 0.14)` 系の暗青紫トーンを基調。
- **キューQ1ハイライト**：`Color(0.3, 0.8, 0.3, 0.4)` の緑系発光（GameUIQueue.gd 158行）と**同系色**で発動可スロットを光らせる → UI言語の一貫性。

### 3-3. 世界観

- ダークファンタジーの暗色基調（黒〜暗青紫）に、発動可能時のみ**魔力が満ちた緑の燐光**が灯る。
- プロトコル装着時（Phase C）のみ、緑を**シアン（0.3, 0.8, 0.9）**へシフト → 「魔術」から「演算」への視覚的切り替え。

## 4. UIコンポーネント一覧

### 4-1. 各スロットの構造

| コンポーネント | サイズ | 位置（slot基準） | 内容 |
|---|---|---|---|
| パネル（`ColorRect`） | 90×130 | (0, 0) | 背景色（状態で変化） |
| 縁取り発光（`ColorRect`） | 94×134 | (-2, -2), z_index=-1 | 発動可能時のみ表示 |
| 状態アイコン（`Label`） | 20×14 | (5, 3) | `▶` / `×` / `·` |
| 呪文名ラベル（`Label`） | 80×32 | (5, 18) | 最大2行・`AUTOWRAP_WORD_SMART` |
| 条件タグ（`Label`） | 80×16 | (5, 52) | `[HP<50%]` 等 |
| コストラベル（`Label`） | 80×14 | (5, 72) | `コスト: 30` |
| 発動可否行（`Label`） | 80×16 | (5, 92) | `▶ 発動可` / `× マナ不足` / `× 条件未達` |
| クールダウンオーバーレイ（`ColorRect`） | 90×130 | (0, 0), z_index=+1 | 発動直後0.3秒のみ表示（黒半透明） |

### 4-2. タイトル

- テキスト：`呪文スロット（左クリック発動／右クリック破棄）`
- 位置：`(base_x, base_y - 18)`
- フォントサイズ：11、カラー：`Color(0.6, 0.7, 0.8)`

### 4-3. ツールチップ（ホバー時・新規）

- 呪文スロットにホバー 0.5秒で表示。
- 表示内容：呪文の詳細効果文（2〜3行）＋発動不可理由（条件詳細）。
- 実装：`Control.mouse_entered` + Timer。

## 5. インタラクション

### 5-1. UI状態遷移

```
┌─────────┐
│  空き   │─── 呪文装填 ──┐
└─────────┘                │
     ▲                     ▼
     │              ┌──────────────┐
  右クリック        │ 装填・待機    │◀──────┐
  （破棄）          │（発動不可）   │       │
     │              └──────────────┘       │
     │                     │               │
     │        マナ/条件満足 │               │ マナ/条件失う
     │                     ▼               │
     │              ┌──────────────┐       │
     └──────────────│ 発動可能      │───────┘
                    │（パネル発光） │
                    └──────────────┘
                           │
                         左クリック
                           ▼
                    ┌──────────────┐
                    │ 発動中        │
                    │（0.3秒演出）  │
                    └──────────────┘
                           │
                    ┌──────┴───────┐
                    │              │
          消費型（消滅）      通常型
                    │              │
                    ▼              ▼
                ┌──────┐      ┌──────────────┐
                │ 空き │      │ 装填・待機    │
                └──────┘      └──────────────┘
```

**注**：要件定義に「クールダウン」フィールドは存在しない。ここでの「発動中」は**発動直後の視覚フィードバック（0.3秒）**を指し、内部状態としてのクールダウン機構は持たない。

### 5-2. 各状態の視覚表現

#### (A) 空き（`spell == null`）
- パネル色：`COLOR_SLOT_EMPTY`（暗転）
- ラベル：`空き`（`COLOR_LABEL_EMPTY`）
- 状態アイコン：`·`（中点、低輝度）
- 縁取り：なし
- アニメーション：なし

#### (B) 装填・発動不可（`can_cast == false`）
- パネル色：`COLOR_SLOT_LOADED_OFF`（グレーアウト）
- ラベル：`COLOR_LABEL_DISABLED`（くすんだ灰）
- 状態アイコン：`×`
- 発動可否行：`× マナ不足` または `× 条件未達`（`COLOR_FAIL_ACCENT` の30%輝度）
- 縁取り：なし
- アニメーション：なし（静的）

#### (C) 発動可能（`can_cast == true`）
- パネル色：`COLOR_SLOT_READY_BG`（緑がかった活性色）
- ラベル：`COLOR_LABEL_READY`（白）
- 状態アイコン：`▶`（`COLOR_READY_ACCENT`）
- 発動可否行：`▶ 発動可`（`COLOR_READY_ACCENT`）
- 縁取り：`COLOR_SLOT_GLOW` の2pxボーダー
- **パルスアニメーション**：縁取りの alpha を 0.55 ⇄ 0.95 で1.2秒周期サインカーブ（`Tween.tween_property(loop)`）

#### (D) 発動中（左クリック直後0.3秒）
- オーバーレイ：黒半透明（`Color(0, 0, 0, 0.4)`）を被せる
- 呪文名ラベルを一瞬白フラッシュ（`modulate = Color(2,2,2)` → `Color(1,1,1)` の0.15秒Tween）
- 縁取り発光を一瞬強調（alpha 1.0 → 0.85）
- その後状態(A)または(B)へ戻る

### 5-3. クリック操作

| 操作 | スロット状態 | 挙動 |
|---|---|---|
| 左クリック | 発動可能 | `cast_spell(i)` 呼び出し → 発動演出 (D) → 状態更新 |
| 左クリック | 発動不可 | **振動アニメーション**（パネルを左右に±3px、0.15秒）＋ 発動可否行を赤フラッシュ |
| 左クリック | 空き | 無反応（クリック吸収のみ） |
| 右クリック | 装填済み（可/不可問わず） | `discard_slot(i)` 呼び出し → 状態(A)へ |
| 右クリック | 空き | 無反応 |

### 5-4. ホバー挙動

| 操作 | 挙動 |
|---|---|
| カーソルON | パネルを1px明るく（`modulate.v += 0.1`） |
| カーソルON 0.5秒経過 | ツールチップ表示（呪文詳細＋発動不可理由） |
| カーソルOFF | ツールチップ非表示・modulate戻す |

## 6. エラーフィードバック（発動失敗時）

### 6-1. 失敗パターンと表示

| 失敗理由 | 発動可否行の表示 | 追加演出 |
|---|---|---|
| マナ不足 | `× マナ不足` | マナゲージを1回赤フラッシュ（0.3秒） |
| 条件未達 | `× 条件未達` | 条件タグを1回赤フラッシュ（0.3秒） |
| スロット空き | `（表示なし）` | 無反応 |

### 6-2. 振動アニメーション詳細

- トリガー：発動不可状態で左クリックされた時のみ
- 実装：`Tween.tween_property(panel, "position:x", base_x + 3, 0.05).set_trans(Tween.TRANS_SINE)` を4回繰り返し（±3px × 4）
- 合計時間：0.15秒
- 目的：「クリックは認識したが発動できない」ことを体感で伝える

### 6-3. 発動成功フィードバック

- 視覚：上記(D) 発動中演出
- 聴覚：呪文固有SE（既存`spell_executor.execute`側で処理、UI側では扱わない）

## 7. プロトコル装着時のUI変化（Phase C）

### 7-1. 装着マーク

- スロット右上隅に **`⚙ AUTO`** 風バッジを追加（14×14px、位置 `(slot_w - 16, 2)`）。
- バッジ色：`Color(0.3, 0.8, 0.9)`（シアン・デジタルトーン）。
- フォント：等幅系フォント使用を指定（`theme_font = "mono"`）→ 「魔術」との質感差別化。

### 7-2. 発光色の切り替え

- プロトコル装着スロットのみ、発動可能時の縁取り発光を**シアン系** `Color(0.3, 0.9, 1.0, 0.85)` に切り替える。
- パルス周期を 1.2秒 → **0.8秒** に短縮（自動化＝機械的リズム）。

### 7-3. 発動時演出の差別化

- 手動発動（魔術）：白フラッシュ
- プロトコル発動（自動化）：シアン縦スキャンライン（`ColorRect` を上→下へ0.2秒で移動）

### 7-4. ラベル表記

- 発動可否行の文言を変更：
  - `▶ 発動可` → `[AUTO.EXEC]`
  - `× マナ不足` → `[STALL: MANA]`
  - `× 条件未達` → `[STALL: COND]`
- **ローマ字＋角括弧＋ドット記法**で「演算規約」の世界観を表現（要件定義 4-3-5 と整合）。

### 7-5. プロトコル未装着スロットとの共存

- 同じ3スロット内で装着/未装着が混在可能。
- UI上は**バッジの有無＋発光色**で区別。
- プレイヤーは「どのスロットが自動で動くか」を一瞥で判別できる。

## 8. UI基準6項目との整合性チェック

### 1. 3秒ルール：この画面で何ができるか3秒で分かるか
- **○ 達成**：
  - 緑に光っているスロット = 今発動できる呪文
  - グレーのスロット = 待機中（不可）
  - 暗いスロット = 空き
  - タイトル文言「左クリック発動／右クリック破棄」で操作も明示
- **根拠**：色と明度の3段階グラデーションで即時判別可能。テキストを読まずとも発動可否が伝わる。

### 2. 視線の一本化：複数の注意点がないか、視線の流れは明確か
- **○ 達成**：
  - 発動可能時のみスロットが光る → **光源は最大3個**に限定
  - 全スロット発動可でも同じ色・同じパルス周期 → 視線は自然と「最初に光ったスロット」へ
  - 盤面（上）→ スロット（下）の縦方向動線が単一
- **留意**：3スロット同時発動可の場合、プレイヤーの選択肢が並列になる → これは**設計上意図した介入判断**なので問題なし。

### 3. 状態の可視化：現在の状態（選択中・購入済み等）が一目で分かるか
- **○ 達成**：4状態を**色・縁取り・アイコン・テキスト**の4重冗長で表現
  - 空き：暗色＋`·`＋「空き」
  - 不可：グレー＋`×`＋失敗理由
  - 可能：緑＋`▶`＋「発動可」＋パルス発光
  - 発動中：黒オーバーレイ＋白フラッシュ
- プロトコル装着状態もバッジ＋発光色変化で明示。

### 4. 操作の最小化：クリック数は最小か、直感的か
- **○ 達成**：
  - 発動：**1クリック**（左クリックのみ）
  - 破棄：**1クリック**（右クリックのみ、既存）
  - 確認ダイアログ・モーダルなし → 観戦リズムを途切れさせない
- **直感性**：「光っているボタンを押す」は全ゲーム共通の普遍的操作。

### 5. 配信映え：視聴者が見ても何をしているか分かるか
- **○ 達成**：
  - 発動可能時の緑パルス発光 → 視聴者にも「次は何か起こる」予感を与える
  - 左クリック → 白フラッシュ → 呪文エフェクト という**因果の明示**
  - プレイヤーの選択タイミング（「光ってから何秒で押したか」）が配信で可視化される
- **介入の見せ場**：「まだ押さないのか？」「今だ！」の緊張がコメント・配信演出の種になる。

### 6. 世界観の匂わせ：ダークファンタジー+無機質な整合性があるか
- **○ 達成**：
  - 基調：暗青紫の石板のような背景 → ダークファンタジー
  - 発動可能時の緑燐光 → 魔力の気配（説明しない）
  - プロトコル装着時のシアン縦スキャンライン → 「この世界は何かの演算系で動いている」匂わせ
  - `AUTO.EXEC` / `[STALL: COND]` 等のローマ字記法 → 無機質さの注入
- **「説明しない、ただそこにある」**：プロトコルの出自・意味はフレーバーテキスト1行のみ。

## 9. 実装時の注意事項（Designerメモ）

### 9-1. パフォーマンス
- 発動可否判定（`can_cast`）は毎フレーム呼ばず、**0.1〜0.2秒間隔のタイマー**で更新する（要件定義 4-1-3 と整合）。
- パルスアニメーションは `Tween.set_loops()` で永続化し、毎フレーム再設定しない。

### 9-2. 既存コードとの差分最小化
- `_build_spell_slots()`：パネル生成ロジックに**縁取り発光用`ColorRect`と状態アイコン`Label`を追加**するのみ。
- `_on_spell_slot_input()`：`MOUSE_BUTTON_LEFT`分岐を追加するのみ。
- `update_spell_slots()`：色・ラベル分岐を3状態→4状態に拡張するのみ。

### 9-3. 動的サイズ縮小の禁止
- スロットサイズは固定値（90×130）を維持。プロトコルバッジは固定位置に配置。
- ウィンドウサイズに応じた縮小は行わない（既存GameUI全体の方針と整合）。

### 9-4. アニメーション時間の指針
- パルス周期：1.2秒（手動）／0.8秒（プロトコル）
- 発動フラッシュ：0.3秒
- 振動（失敗）：0.15秒
- ホバー表示遅延：0.5秒
- 短すぎるとちらつき、長すぎると観戦テンポを損なうため、上記値を標準とする。
