## 1. 目的と位置付け

### 1.1 Designerとして本Sprintで担う領域

Sprint 7 は「建物カードを使って建物が建つまで」のフローを内部実装する段階である。
企画書 §11.2 に示されるとおり、**建設中UI・建設ログ・建物詳細UIの作り込みは Sprint 8 対象** であり、
Sprint 7 では「最小限・既存UIの拡張のみ」で動作確認できるレベルを目標とする。

Designerが Sprint 7 で押さえるべき領域は以下4つ。

| 領域 | 対象 | Sprint 7 の作り込み深度 |
|---|---|---|
| 建物カード使用フロー | 手札 → 建設予定地指定 → 建設開始 | 既存BUILDカード操作の延長で完結（最小） |
| 建物状態の3区分表現 | 未建設 / 建設中 / 稼働中（停止中） | 盤面パネル上のミニマル表示（必須） |
| 人手スライダー | 稼働人手/作業人手の配分UI | フッター内に1本のスライダー枠を新設（必須） |
| 建設進捗ゲージ | 建設中パネル上のリングゲージ | パネル中央上に円弧で表示（必須） |

### 1.2 核となる体験との整合確認

> 「盤面を設計して、介入を仕込んで、答え合わせを観戦する」

- 建物カード使用は **「盤面設計」** そのもの。配置の選択肢を絞る制約（自建物隣接・開示済み）が体験の核を支える
- 人手スライダーは **「介入」** にあたる。バトル中でも稼働/作業の比率を1操作で変えられるべき
- 建設進捗・稼働状態は **「観戦対象」**。プレイヤーが手を出さなくても進捗が進む様子が見える

### 1.3 KISS原則の遵守

- 建設状態は **3区分（未建設・建設中・稼働中）** に限定。「停止中」は稼働中の派生として表現（独立アイコンを増やさない）
- 人手スライダーは **1本のみ**（稼働 ↔ 作業の二択）。3軸以上に分けない
- **新規色定義は0個**。既存 `COLOR_*` 定数のみで状態表現する
- 建設ログは Sprint 7 では作らず、Sprint 8 まで遅延

## 3. 画面フロー（建物カード使用 → 建設完了）

```
[1] 手札に建物カード表示（FOOTER BUILDブロック）
  ↓ クリック
[2] 配置モード ON
  ・盤面の「自建物隣接 ∧ 未建設土地 ∧ 資源開示済み」マスを
    緑枠 (COLOR_WOOD) でハイライト + パルス（1.0sサイクル）
  ・配置不可マスは無反応
  ・FOOTER右端 PLACE-ON-BOARD ヒント表示
  ↓ マスクリック
[3] 建設コストチェック
  ・資源不足 → カード自体に「!」アイコン表示（既存実装流用）+ 短い赤フラッシュ
  ・OK → 続行
  ↓
[4] 建設予定地化（瞬時）
  ・該当パネルに半透明マスク（α=0.4）
  ・パネル中央上に建設リングゲージ表示開始（0%）
  ・建物カード手札から消費（除外 or 捨て札）
  ↓
[5] 建設進捗（リアルタイム）
  ・作業人手が足りる間：リングゲージが時計回りに伸びる
  ・作業人手不足：リングゲージが灰色化（COLOR_TEXT_DIM）して停止
  ↓ 100%到達
[6] 建設完了演出（300ms）
  ・リング消滅、半透明マスク消滅
  ・パネルの建物アイコンが既存色でフェードイン
  ・パネル下部に稼働ドット（緑）出現
  ↓
[7] 稼働中
  ・稼働人手が足りる間：稼働ドット = 緑
  ・稼働人手不足：稼働ドット = 灰色（COLOR_TEXT_DIM）
```

### 3.1 操作カウント

| 操作 | クリック数 |
|---|---|
| カード使用 → 建設予定地指定 → 建設開始 | 2クリック（カード→マス） |
| 人手配分変更 | 1ドラッグ または ±ボタン1クリック |
| キャンセル | Sprint 7 非対応（企画書 §4） |

## 4. 盤面パネルの状態表現（建設中UI詳細）

### 4.1 4状態の視覚区別

3秒ルール検証の主要対象。**色 + 形状 + 装飾要素** の組み合わせで瞬時識別を狙う。

| 状態 | パネル背景 | パネル枠 | 中央 | 下部装飾 |
|---|---|---|---|---|
| 未建設土地（資源開示済み） | 既存（資源色） | 既存 | 資源アイコン | なし |
| **建設予定地（建設中・進行中）** | 半透明マスク（COLOR_PANEL × α=0.4） | COLOR_ACCENT_GOLD 1px | リングゲージ（COLOR_ACCENT_GOLD） | なし |
| **建設予定地（建設中・停止中=作業人手不足）** | 同上 | 同上 | リングゲージ（COLOR_TEXT_DIM・灰色） | なし |
| **建設後パネル（稼働中）** | 既存（建物色・不透明） | 既存 | 建物アイコン | 稼働ドット（緑系・COLOR_WOOD） |
| **建設後パネル（停止中=稼働人手不足）** | 既存（建物色・α=0.7に減衰） | 既存 | 建物アイコン | 稼働ドット（COLOR_TEXT_DIM・灰色） |

### 4.2 建設リングゲージ仕様

```
┌─────────────────┐
│       ●●●        │  ← パネル上端
│     ●     ●      │     リング外径 28px
│    ●  74%  ●     │     リング内径 22px（線幅 3px）
│     ●     ●      │     進捗：時計回りに角度伸長 (0% = 0°、100% = 360°)
│       ●●●        │     色：進行中 = COLOR_ACCENT_GOLD
│                   │         停止中 = COLOR_TEXT_DIM
│   [建物アイコン]  │  ← パネル中央（建設中は半透明 α=0.4）
└─────────────────┘
```

- リング下に進捗% を表示するか：**しない**（KISS原則・3秒で「進んでいる/止まっている」が分かれば十分）
- リング描画は `_draw()` で `draw_arc()` 利用
- リング背景：薄い円（COLOR_BORDER 1px）で「ここがリングの軌道」を提示

### 4.3 稼働ドット仕様

建設後パネル下部に1個のドットを置く。状態をパネルの **色 + ドット** の二重表現にすることで、視聴者が遠目にも識別できる。

| 状態 | ドット色 | パネル不透明度 |
|---|---|---|
| 稼働中 | `COLOR_WOOD` (#3F6932 緑系) | 1.0 |
| 停止中（稼働人手不足） | `COLOR_TEXT_DIM` (#8A8070 灰色) | 0.7 |

- ドットサイズ: 直径 6px
- 位置: パネル中央下端から 4px 内側
- 描画: `draw_circle()`

> **判断:** 既存EconBuilding.gd:454-460 の HP バーは Sprint 7 範囲外（HP は将来Sprintで導入）。今回は **稼働状態のみ** をドットで示す。情報密度を上げない。

### 4.4 配置可能マスのハイライト（土地カード配置の流用）

Sprint 9 で土地カード配置時に作った「緑パルス」表現を、Sprint 7 の建物カード配置時にも流用する。

| 状態 | 表現 |
|---|---|
| 配置可能（自建物隣接・未建設・開示済み） | 枠線 `COLOR_WOOD` 2px + パルス（α 0.5↔1.0、1.0sサイクル） |
| 配置不可（自建物非隣接） | 枠線なし（通常表示） |
| 配置不可（建設予定地・建設後パネル） | 枠線 `COLOR_RED` 1px + α=0.3 で暗転 |
| ホバー中の配置可能マス | 枠線 `COLOR_ACCENT_GOLD` 3px に強調 |

> **判断:** Sprint 9 と同じ規則を使うことで、プレイヤーの学習コストを削減する。緑パルス = 「ここに置ける」の統一サイン。

## 5. 人手スライダー UI 詳細

### 5.1 配置・サイズ

フッター中央に新設する LABOR ブロック（160 × 180）。

```
┌──────────────────┐
│ — LABOR —        │  ← 24px ヘッダー
├──────────────────┤
│ TOTAL  6         │  ← 12px：人手総量（読み取り専用）
│                  │
│ ◤━━━━●━━━━◢   │  ← 36px：水平スライダー（メイン）
│                  │
│ OPS   70%  4    │  ← 22px：稼働人手（割合% + 実数）
│ WORK  30%  2    │  ← 22px：作業人手（割合% + 実数）
│                  │
│ [-] [+]          │  ← 22px：±10% 微調整ボタン
└──────────────────┘
```

### 5.2 スライダー操作

| 操作 | 動作 |
|---|---|
| つまみドラッグ | OPS:WORK 比率を10%刻みで変更（10%-90%の範囲） |
| `[-]` ボタン | OPS を10%減らす（WORK が10%増える） |
| `[+]` ボタン | OPS を10%増やす（WORK が10%減る） |
| ホバー（つまみ） | つまみ拡大（ハイライト COLOR_ACCENT_GOLD） |
| ドラッグ中 | リアルタイムで OPS / WORK 数値が更新 |

### 5.3 視覚表現

```
スライダー本体（128px幅）：
   ◤━━━━━━━━━━━━━━━━━━━━━●━━━━━━◢
   ↑ OPS側塗り（COLOR_ACCENT_GOLD）   ↑ WORK側塗り（COLOR_BORDER）
                          つまみ：直径 12px の円（COLOR_TEXT 縁取り）
```

- 左寄り = OPS優位、右寄り = WORK優位
- 塗り分けで現在の比率が一目で分かる
- 初期値: OPS 70% / WORK 30%（企画書 §7.3 に準拠）
- 刻み: 10%（企画書 §7.3 に準拠）

### 5.4 状態の可視化（人手不足の警告）

| 状態 | 表現 |
|---|---|
| OPS 不足（稼働建物が止まっている） | OPS行の数値が `COLOR_RED` (#9C3A2A) で点滅（1.0sサイクル） |
| WORK 不足（建設が止まっている） | WORK行の数値が `COLOR_RED` で点滅 |
| 不足解消 | 即座に通常色 `COLOR_TEXT` に戻る |

> **判断:** 「警告アイコン+テキスト」ではなく「数値の色変化」のみに留める（情報過多防止・KISS）。プレイヤーは数値の赤化を見て即座にスライダーを動かす動機を得る。

### 5.5 既存 BUILD ブロックへの影響

BUILD ブロックは 420px → **260px** に圧縮する。

| 項目 | 変更前（既存） | 変更後（Sprint 7） |
|---|---|---|
| カード枚数 | 4枚（兵舎・要塞・工房・農村） | 5枚（手札の5枚スロット） |
| カードサイズ | 92×140 | **48×140**（圧縮） |
| カード間スペース | 8px | 4px |
| 表示内容 | アイコン + 名称 + コスト | アイコン + コスト（名称はホバーで表示） |

**初期デッキ13枚は手札に5枚ずつ表示。残りはデッキ/捨て札（Sprint 7 では既存のドロー表示を流用）。**

> **判断:** 既存4種固定→5枚手札への切替が最大の構造変更だが、**既存BUILDカード形状を縮小して再利用**する方針で新規UIを最小化する。名称はホバーで補完。

## 7. 3秒ルール検証

### 7.1 各UI要素の理解度チェック

| UI要素 | 3秒で伝わるか | 根拠 |
|---|---|---|
| 未建設土地 | ◎ | 既存表現を継承 |
| **建設中（建物が建っている途中）** | ◎ | 半透明マスク + リングゲージで「これは未完成」が即座に分かる |
| **建設中・停止中（作業人手不足）** | ◯ | リングが灰色化することで「進んでいない」が伝わる。WORK数値の赤点滅と二重に伝達 |
| **稼働中** | ◎ | パネル不透明 + 緑ドットで「動いている」が即理解 |
| **稼働中・停止中（稼働人手不足）** | ◯ | パネル α=0.7 + 灰色ドット + OPS数値の赤点滅で三重伝達 |
| 人手スライダー | ◎ | 左塗り（OPS）と右塗り（WORK）の比率が一目で分かる |
| 配置可能マス | ◎ | 緑パルスでハイライト |

### 7.2 視線の一本化チェック

| シーン | 注意点が一本化されているか |
|---|---|
| バトル中（通常） | ◯ 盤面（メイン）+ FOOTER左→中央→右の流れ：HARVESTER配分 → 人手配分 → 建物選択 |
| 建物カード使用中 | ◎ FOOTER暗転（α=0.6）+ 盤面の配置可能マスに集中 |
| 建設完了演出時 | ◎ 該当パネル1点に集中（盤面全体は変化しない） |
| 人手不足発生時 | ◯ LABORブロックの該当行（OPS or WORK）の赤点滅に視線誘導 |

### 7.3 状態の可視化チェック

| 状態 | 可視化方法 | 二重化（色+形状） |
|---|---|---|
| 未建設 | 既存表現 | - |
| 建設中・進行中 | 半透明マスク + 金色リング進行 | 色（金）+ 形（リング進行） |
| 建設中・停止中 | 半透明マスク + 灰色リング | 色（灰）+ WORK数値の赤点滅 |
| 稼働中 | 不透明 + 緑ドット | 色（緑）+ ドット位置（下部） |
| 稼働中・停止中 | α=0.7 + 灰色ドット | 色（灰）+ OPS数値の赤点滅 |

## 9. UI基準6項目チェック（最終）

| # | 基準 | 評価 | 根拠 |
|---|---|---|---|
| 1 | **3秒ルール** | ◎ | 建物の3状態（未/中/完）が色 × 形状 × 装飾の三重表現で識別可能 |
| 2 | **視線の一本化** | ◯ | 盤面メイン + FOOTER左→中→右の意思決定順。LABORが新規挿入されるが、HARVESTERの右隣で論理連続性あり |
| 3 | **状態の可視化** | ◎ | 5状態すべてに二重以上の表現を割り当てた。色のみに頼らない |
| 4 | **操作の最小化** | ◎ | カード使用2クリック、人手配分1ドラッグ、ドラッグ操作なし、確認ダイアログなし |
| 5 | **配信映え** | ◎ | リング進行・スライダー位置・赤点滅警告で視聴者の理解を補助 |
| 6 | **世界観の匂わせ** | ◎ | 既存色定数のみ使用、装飾線・大文字英字・記号アイコン継承、説明的ツールチップなし |

**総合: 6項目すべて合格水準（基準2のみ◯、その他は◎）**

## 10. 残論点・次フェーズ

### 10.1 Designer視点の残論点（要件定義フェーズで確定）

| 項目 | 残論点 | 推奨判断 |
|---|---|---|
| BUILD ブロックのカード表示形式 | 4枚固定 vs 手札5枚 | **手札5枚（48×140に圧縮）** を推奨。初期デッキ13枚に対応するには手札方式が必須 |
| 建設リング下に進捗%表示 | あり vs なし | **なし** を推奨（KISS・3秒で進む/止まるが分かれば十分） |
| 稼働ドットの個数 | 1個（状態のみ） vs 複数（人手数表現） | **1個（状態のみ）** を推奨。人手数の詳細は LABORブロック側で表現 |
| 人手スライダー刻み | 10%固定 vs 可変 | **10%固定** を推奨（企画書 §7.3 準拠・KISS） |
| 人手不足の警告表現 | アイコン+テキスト vs 数値色変化のみ | **数値色変化のみ** を推奨（情報過多防止） |
| 建設キャンセル | 可 vs 不可 | **不可** を推奨（企画書 §4 で MVP 非対象と明記） |
| 配置不可カードの表現 | 全カード暗転 vs 警告のみ | **警告のみ（!アイコン + 赤フラッシュ）** を推奨。既存実装の流用 |
| 建設予定地の半透明マスク色 | COLOR_PANEL vs COLOR_BG | **COLOR_PANEL × α=0.4** を推奨（既存パネルとなじむ） |
| 建設リング配置位置 | パネル中央 vs パネル中央上 | **パネル中央上** を推奨（建物アイコン位置を侵さない） |

### 10.3 要件定義書に渡す確定事項リスト

Architect が要件定義書を起こす際の **Designer承認済み事項**:

1. **新規UI座標・サイズ**:
   - LABORブロック（フッター中央）: 160 × 180、x=700-860
   - BUILDブロック（圧縮）: 260 × 180、x=860-1120
   - PLACE-ON-BOARDヒント（既存）: 160 × 180、x=1120-1280
   - 建設リングゲージ: 直径28px、パネル中央上
   - 稼働ドット: 直径6px、パネル中央下
   - スライダー本体: 128 × 12px、つまみ直径12px

2. **使用する色定数**:
   - 既存EconMain.gd の `COLOR_*` 定数のみ
   - 新規色定義は **追加しない**

3. **アニメーション仕様**:
   - 配置可能マスパルス: 1.0sサイクル
   - 建設完了フェードイン: 300ms
   - 資源不足赤フラッシュ: 500ms
   - 人手不足数値点滅: 1.0sサイクル

4. **インタラクション**:
   - 建物カード使用: カードクリック → マスクリック（2クリック）
   - キャンセル: Sprint 7 非対応
   - 人手スライダー: ドラッグ または ±ボタン
   - 配置不可: 何も起きない（クリック非反応）

5. **状態の可視化ルール**:
   - 建設中: 半透明マスク α=0.4 + 金色リング
   - 建設停止: 灰色リング + WORK数値赤点滅
   - 稼働中: パネル不透明 + 緑ドット
   - 稼働停止: パネル α=0.7 + 灰色ドット + OPS数値赤点滅

6. **新規UI最小化方針**:
   - 建設ログ・建物詳細UIは Sprint 7 では作らない
   - Sprint 8 の作り込みフェーズで追加する
