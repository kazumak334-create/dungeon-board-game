## 1. 概要

### 1.1 何を実現するか

「盤面を設計して、介入を仕込んで、答え合わせを観戦する」という核体験を、
**建物プリセット型** の準備フェーズで具体化する。

- バトル前：8種の基本建物から使うものを選び、各建物の上位バリアントを準備予算（G）で解放し、
  Lv2→Lv3の変態先（ツリー）を確定する
- バトル中：プレイヤーは配分（ALLOC）操作で介入。建物・ユニット・マイルストーンが自動進行
- バトル後：交易ボーナス（G）が次ランの準備予算に上乗せされる

主要決断は **バトル前に完結**。バトル中は基本観戦＋配分介入のみ。

### 1.2 設計の柱

| 柱 | 内容 |
|----|------|
| 建物プリセット | 8種の基本建物は常に開放。組み合わせと派生で多様性を出す |
| 上位バリアント | バトル前に予算で解放。ランごとにリセット（毎ラン違うビルド） |
| 4軸マイルストーン | バトル中に自動進行するグローバル効果（建物解放はしない） |
| 新リソース | Iron（希少・施設アップグレード）/ Cotton（強化軸の燃料） |
| 完全観戦 | バトル中の主要決断はなし。配分介入のみ |

## 2. 建物システム

### 2.1 基本建物（8種・常に開放）

| カテゴリ | 建物名 | 役割 | 主資源 |
|---------|-------|------|-------|
| 軍事 | 兵舎 | 攻撃ユニット生産 | Wood |
| 軍事 | 要塞 | 守備ユニット生産 | Stone |
| 軍事 | 工房 | 崩しユニット生産 | Sulfur |
| 経済 | 農村 | Wheat供給 | Wood + Wheat |
| 経済 | 製材所 | WOODタイル隣接で採取量+1/trip | Wood |
| 経済 | 鉱山 | STONE/SULFUR/IRタイル隣接で採取量+1/trip | Sulfur |
| 支援 | 交易所 | 資源 → G変換（既存RestScreen交易タブと連携） | - |
| 支援 | 装備屋 | ユニット種別バフ（既存RestScreen装備タブと連携） | Cotton |

※ BASE は別枠・固定（建物枠としては数えない）

### 2.2 建物レベルシステム

```
Lv1（基本）  →  Lv2（強化選択）  →  Lv3（変態：上位バリアントへ）
```

| レベル | 内容 | 解放方式 |
|-------|------|---------|
| Lv1 | 基本建物。常に使用可能 | デフォルト |
| Lv2 | 強化選択（**方式は未確定・残論点 #1**） | 条件達成後にプレイヤー選択 |
| Lv3 | バトル前に確定したツリーに従い、上位バリアントへ変態 | バトル前準備フェーズで確定 |

### 2.3 上位バリアント（派生先）

- 各基本建物に **複数の派生バリアント** が存在（建物ごとの種類・内容は **残論点 #2**）
- バリアントは **毎ラン準備予算（G）で解放**。**ランをまたいだ永続化はしない**
- 解放されたバリアントの中から1つを Lv3 変態先として選ぶ

### 2.4 製材所・鉱山（新建物）の隣接ボーナス

| 建物 | 隣接条件 | 効果 |
|------|---------|------|
| 製材所 | WOODタイル隣接に建設 | 同タイルのハーベスター採取量 +1/trip |
| 鉱山 | STONE / SULFUR / IRタイル隣接に建設 | 同タイルのハーベスター採取量 +1/trip |

- 鉱山には **Sulfurコスト** が必要（具体値は **残論点 #4**）
- IRタイル（Iron採取）は鉱山経由のみ（後述）

### 2.5 ユニット派生

- 基本3種（突 / 守 / 崩）の役割は維持
- **建物バリアントによって派生ユニットが変わる**（例：飛行突、重装突）
- 1ランで登場するユニット種は **6種程度** を想定

## 3. バトル前準備フェーズ

### 3.1 フロー

```
【バトル前準備】
 1. 8種の基本建物から「このバトルで使うもの」を選択
 2. 各建物の上位バリアントを準備予算（G）で解放
 3. Lv2→Lv3 のツリー（変態先）を確定
 4. バトル開始 → 完全観戦（配分介入のみ）
【バトル後】
 5. 交易ボーナスが次ラン準備予算に上乗せ
```

### 3.2 設計指針

- 「長い準備＝OK」「作業的な繰り返し＝NG」
- **全建物を一画面で見渡して決める** 設計（タブ切替・ページめくりは避ける）
- ドラフト（8種から選抜）の有無は **残論点 #8**

### 3.3 準備予算 G

```
毎ラン準備予算 = 基本量（固定支給） + 前ラン交易ボーナス
```

- 基本量：**残論点 #6**
- 前ラン交易ボーナス：交易軸マイルストーンLv × 2G（暫定値・残論点 #6）
- 既存の永続Gゴールド（`econ_mvp_roguelite_requirements.md`）とは **別カウント**
  - 永続G：装備購入・施設強化（Lv2強化）に使用（既存）
  - 準備予算：バリアント解放のみに使用（本書・新規）
  - **未確定：永続Gと準備予算を統合するか分離するかは残論点 #6 に含める**

## 4. 4軸マイルストーンシステム

### 4.1 全体仕様

- バトル中に **自動進行** するグローバル効果
- マイルストーンでは **建物の解放はしない**（建物はバトル前に確定済み）
- 4軸並行進行。バトル中の配分・行動が条件達成のトリガーになる

### 4.2 採取強化軸（BUILD配分が進める）

| Lv | 効果 | 条件イメージ |
|---|---|---|
| 1 | ハーベスター移動速度 +15% | BUILD×2配分 |
| 2 | 製材所解放 | BUILD×5累計 |
| 3 | 鉱山解放 | Iron初回採取 |
| 4 | Iron採取枠解放・採取量 +50% | Iron×20蓄積 |
| 5 | 全ハーベスター採取量 ×2 | Iron×50蓄積 |

### 4.3 ユニット生産軸（ユニット生産数が進める）

| Lv | 効果 | 条件 |
|---|---|---|
| 1 | 全建物の生産間隔 -15% | 生産10体 |
| 2 | 生産コスト -20% | 生産20体 |
| 3 | 生産間隔 -35% | 生産40体 |
| 4 | 生産コスト 半額 | 生産70体 |
| 5 | 生産1回につき2体出撃（同コスト） | 生産100体 |

### 4.4 ユニット強化軸（Cotton消費で進める）

| Lv | 効果 | 条件 |
|---|---|---|
| 1 | 全ユニットHP +15% | Cotton×5 |
| 2 | 全ユニットATK +20% | Cotton×15 |
| 3 | 全ユニット移動速度 +25% | Cotton×30 |
| 4 | 兵種固有効果解放（Attacker連続 / Tank反撃 / Breaker巻込） | Cotton×50 |
| 5 | 撃破されたユニットが生産コストを返却 | Cotton×80 |

### 4.5 交易軸（TRADE配分が進める・二面性あり）

| Lv | 効果 | 条件 |
|---|---|---|
| 1 | 変換レート改善 | TRADE配分×2 |
| 2 | 余剰 Wood/Stone → Wheat 自動変換 | 交易総量×20 |
| 3 | 任意リソース間相互変換 | 交易総量×50 |
| 4 | 交易で Iron 取得可能 | 交易総量×100 |
| 5 | TRADEハーベスターが敵採取を一部横取り | 交易総量×200 |

#### 二面性

- **今のバトル**：資源変換・効率改善（即時効果）
- **次ラン以降**：準備予算G上積み（**交易軸Lv × 2G**、暫定値・残論点 #6）

### 4.6 達成条件の数値

すべてのLv達成条件の具体値は **残論点 #5** で確定する（上記は暫定）。

## 5. 新リソース

### 5.1 Iron（鉄）

| 項目 | 内容 |
|------|------|
| 産出 | 山岳隣接タイル（IRタイル）のみ |
| 希少性 | 高（マップ内に少数） |
| 採取手段 | 鉱山（IRタイル隣接に建設）+ 採取強化軸Lv4で枠解放 |
| 用途 | 施設アップグレード（Lv2強化）の主要コスト |
| 既存との関係 | `design_iron_cotton_resources.md`（個人memory）の方針を継承。本書で正式化 |

### 5.2 Cotton（綿）

| 項目 | 内容 |
|------|------|
| 産出 | 新ハーベスターカテゴリ（**詳細は残論点 #4**） |
| 用途 | ユニット強化軸の燃料（Lv1〜5の進行リソース） |
| 装備屋連携 | 既存装備屋の主資源として併用（Cotton消費 → 装備バフ） |

### 5.3 既存資源との整合

- Wood / Stone / Sulfur / Wheat：既存通り
- 小麦システムは現行（実装済み）通り：
  - マクロ消費廃止（EconEconomy.update は何もしない）
  - ユニット個別空腹のみ（1 wheat / ユニット / 5秒）
  - 餓死：max_hp を10秒で削り切る

## 6. データ構造（暫定）

```gdscript
# 建物データ（GameSession or 専用クラスで管理）
{
    "building_id": String,         # "barracks" | "fortress" | "workshop" | "village" | "lumber_mill" | "mine" | "trade_post" | "armory"
    "category": String,            # "military" | "economy" | "support"
    "current_level": int,          # 1..3
    "selected_for_run": bool,      # バトル前準備で「使う」と選択されたか
    "unlocked_variants": Array,    # 当該ランで解放済みバリアントID一覧
    "lv3_variant_id": String,      # Lv3変態先として確定済みのバリアントID（""=未確定）
}

# バリアントデータ（カタログ・読み取り専用）
{
    "variant_id": String,
    "parent_building_id": String,
    "display_name": String,
    "unlock_cost_g": int,          # 準備予算Gでの解放コスト
    "effect_summary": String,      # UI表示用
}

# マイルストーン進行（GameSession）
{
    "axis": String,                # "harvest" | "production" | "enhance" | "trade"
    "current_level": int,          # 0..5
    "progress_value": float,       # 当該Lvの達成条件に対する累積値
}

# 準備予算
{
    "g_run_budget": int,           # 当該ランの準備予算（バトル前に消費可）
    "g_carryover_from_trade": int, # 前ラン交易軸ボーナス
}
```

※ 既存 `EconEconomy.gd` / `GameSession.gd` への追加方法は実装フェーズで確定。

## 7. 既存システムとの整合性チェック

### 7.1 GAME_DESIGN.md との整合性

- 「盤面を設計→介入を仕込む→答え合わせを観戦」を維持 → ✅
- 完全オートバトル維持 → ✅（バトル中の主要決断なし）
- 廃止済み設計（盤面召喚・本体直接攻撃 等）に抵触しない → ✅
- 3秒ルール：マイルストーンの効果は「全体の数値変化」で見て分かる → ✅

### 7.2 KISS原則

- 建物は8種固定。種類は増やさない（多様性は **バリアント** で出す）
- 4軸マイルストーンの効果はすべて **既存パラメータの倍率変更** で表現（新フィールド最小化）
- 新リソースは Iron / Cotton の2種のみ。これ以上増やさない

### 7.3 疎結合ルール（EconMVP）

- 建物選択・バリアント解放は **専用マネージャ経由** で状態変更
- 他クラスの内部配列・フィールドへの直接代入は禁止（CLAUDE.md準拠）

## 12. 建物バリアント一覧（初期選択型・バリエーション）

更新日: 2026-05-01
STATUS: 確定

### 設計方針

- **初期バリアント**：ゲーム開始前に選ぶ横並びの選択肢（上位互換ではない）
- 全生産建物のベース生産間隔：**20秒**（隣接ボーナスなしは実質機能しない重さ）
- 配置ボーナス条件を満たすと：**生産時間・コスト 半減**
- 配置ボーナス条件：原則は農村隣接 / 採掘守備要塞・砲塔要塞は鉱山隣接

---

### 兵舎（突撃）3案

| バリアント名 | 特性 | コスト/間隔 | 配置ボーナス条件 |
|------------|------|------------|---------------|
| 斥候兵舎 | 飛行突撃・地形無視移動 | Wood3/20秒 | 農村隣接で半減 |
| 群兵舎 | 2体同時出撃・各HP/ATK半減 | Wood3/20秒 | 農村隣接で半減 |
| 徴兵兵舎 | Wood不要・Wheat2消費 | Wheat2/20秒 → 農村隣接で10秒 | 農村隣接で半減 |

---

### 要塞（守備）4案

| バリアント名 | 特性 | コスト/間隔 | 配置ボーナス条件 |
|------------|------|------------|---------------|
| 砲塔要塞 | 射程3後方射撃型守備ユニット生産 | Stone4/20秒 | 農村隣接で半減 |
| 採掘要塞 | 生産ごとStone+1産出 | Stone4/20秒 | 農村隣接で半減 |
| 採掘守備要塞 | 通常守備 | Stone3/20秒 | **鉱山隣接**で半減 |
| 投石要塞 | ユニット非生産・建物自体が石を消費して遠距離攻撃 | Stone2/発（攻撃間隔3秒、射程5、ダメージ30） | 農村隣接で半減 |

**投石要塞の詳細：**
- 建設コスト: Stone4
- 攻撃方式: 3秒ごとにStone2を消費して射程5の敵に30ダメージ
- DPS目安: 10/秒（守備ユニット1体DPS 12.5と同等水準）
- ユニット生産なし（攻撃は建物本体が行う）

---

### 工房（崩壊）2案

| バリアント名 | 特性 | コスト/間隔 | 配置ボーナス条件 |
|------------|------|------------|---------------|
| 長射程崩壊工房 | 射程5の崩壊ユニット（遠方から自爆） | Sulfur4/20秒 | 農村隣接で半減 |
| 連爆崩壊工房 | 隣接する突撃ユニットが攻撃した瞬間に連鎖起爆 | Sulfur3/20秒 | 農村隣接で半減 |

**長射程崩壊の詳細：**
- HP: 40 / ATK（爆発）: 35 / 射程: 5（min_range: 5）
- 既存崩壊（HP70, ATK25, 射程3-3）より脆く威力高め
- 前線まで移動不要・遠距離から単体爆撃

**連爆崩壊の詳細：**

## 15. 一斉突撃システム（設計確定）

### ゲームタイトル
「一斉突撃」

### コアコンセプト
- ユニットは生産されると生産建物にアイドリング待機する
- プレイヤーが「旗を横に倒す（1秒長押し）」で全ユニットが一斉突撃
- 「盤面を設計して、気を見て一斉突撃し、結果を観戦する」がゲームの核

### 旗の動作

| 状態 | 動作 |
|---|---|
| 旗縦（デフォルト） | 生産ユニットはアイドリング待機 |
| 旗横（突撃モード） | 全アイドルユニットが突撃 + 新規生産ユニットも即前線供給 |
| 旗を縦に戻す | 前線ユニットはそのまま戦い続ける / 新規生産からアイドリングに戻る |

波状攻撃（旗を複数回切り替えて第1波・第2波を送り込む）も戦術として成立する。

### スタック仕様
- 生産建物ごとにスタック上限: **3体**
- スタックが満杯になったユニットは自動的に集結点へ移動

### 生産速度
- 農村/鉱山隣接ボーナスあり: **5秒**
- 隣接ボーナスなし: **20秒**

### 集結点（ラリーポイント）
- マップ上に置けるフラグ（建物ではない・建設コストなし）
- 生産建物に紐づけられ、ユニットは生産後に自動的に集結点へ向かう
- 集結点では**1ユニット1マス**で周囲に六角形状に展開（スタックしない）
- 集結点が埋まるほど視覚的に軍の規模がわかる
- 敵には集結点の位置・ユニット数が見えない（奇襲設計を可能にする）
- 現フェーズでは集結点は1箇所（複数は操作が煩雑なため後フェーズ対応）

### 小麦消費とのインタラクション
- アイドリング中のユニットも小麦を消費する
- 軍を貯めすぎると食糧難になる → 「どれだけ貯めるか」が判断のジレンマになる
- 小麦が自然な軟上限として機能する

### 非戦闘ユニット
- ハーベスターは突撃指示の影響を受けず採取を継続する

### 敵AI
- 同じ一斉突撃ロジックで動作（PvP前提の対称設計）
- カウンター型: プレイヤーの突撃を受けきって消耗後にカウンター発射
  - 同時発射はメリットなし → 相手が消耗した瞬間を狙う方が有利

### 読み合い構造

```
プレイヤー: 軍を貯めてタイミングを測る
  → 突撃 → 敵が受けきる
  → 敵: プレイヤーが消耗した瞬間にカウンター
  → プレイヤー: 第2波で迎え撃つ or 防衛に切り替える
```

## 16. ハーベスター採取範囲制限（設計確定）

- ハーベスターは「自分の建物の半径3マス以内」にある資源タイルのみ採取できる
- 「自分の建物」= プレイヤー側（is_player_side: true）かつ建設済み（is_built: true）のすべての建物
- ゲーム内でグロー表示されている自エリア = 採取可能範囲（視覚的に一致）
- プレイヤーは自建物を増やす・前に出すことで採取範囲を拡大できる
- 敵側ハーベスターも同様のルールで動く（プレイヤーの建物は参照しない）
- 実装: `_try_move_with_villages()` および `_try_move()` でターゲット候補を絞る
  - 候補タイルを `grid.hex_distance(tile_pos, b.grid_pos) <= 3` で全プレイヤー建物に対してチェック
  - 1つでも条件を満たす建物があるタイルのみ採取対象とする

## 17. 農村配置制限なし（設計確定）

- 農村（VILLAGE）はプレイヤーエリア（col 0〜7）内であればどこでも配置可能
- 特別な配置制限は設けない（EconMain.gd に農村固有の制限がある場合は削除する）
- 既存の配置ボーナス（農村隣接で生産5秒・コスト半減）はそのまま維持

## 18. 生産速度仕様（確定値）

- 全生産建物のベース生産間隔: **20秒**
- 農村または鉱山隣接ボーナスあり: **5秒**（`BARRACKS_PRODUCE_INTERVAL / 2.0` ではなくハードコード値 `5.0` を使用）
- EconBuilding.gd の `_update_barracks` / `_update_fortress` / `_update_workshop` において
  `_placement_bonus_active` が true の場合の interval は `5.0` を直接指定する

## 19. 奇襲隊フラグ（経由旗）概念設計

STATUS: 企画確定・実装未定（複数旗UIの安定後に実装予定）
更新日: 2026-05-01

### 19.1 概念定義

集結点（ラリーポイント）に「接続あり旗（集結旗）」と「接続なし旗（経由旗）」の2種を設ける。

| 旗の種類 | 定義 | 視覚 |
|---------|------|------|
| 集結旗（接続あり） | 特定の生産建物と紐づけられた旗。ユニットの待機場所 | 黄色 #FFD700 |
| 経由旗（接続なし） | どの建物とも紐づいていない旗。突撃時の通過点 | 淡青 #7EC8E3 |

### 19.2 奇襲として機能するメカニズム

1. プレイヤーが経由旗を山岳や建物の裏などに設置する
2. 突撃指示時、ユニットは「集結旗 → 経由旗 → 敵BASE」の順に経路を設定する
3. 経由旗はプレイヤーにしか見えない（§15 の「敵には集結点の位置が見えない」仕様を継承）
4. 結果：敵は「どこからユニットが来るか」を予測できず、回り込み奇襲が成立する

### 19.3 最小仕様（実装時に必要なもの）

1. 旗に `is_connected: bool` フラグを持たせる
2. 突撃時の経路計算に「最も近い経由旗を経由する」オプションを追加
3. 経由旗の色をユニットが集まらない旗として視覚的に区別（淡青）

### 19.4 実装フェーズの推奨タイミング

複数旗UI（`docs/meta/req_econ_rally_point.md`）の実装が安定した後の次スプリント。
