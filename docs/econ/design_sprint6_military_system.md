# Sprint 6：兵数・ユニット変換・防衛突破人口被害企画書 確定版

## 1. 目的

Sprint 6では、人口・満足度から内部兵数を算出し、内部兵数から攻城戦用の基本ユニットを生成する。

また、防衛突破時に都市被害として人口を即時減少させる。

本企画書は、兵数・ユニット変換・スタック化・特殊ユニット拡張方針・防衛突破人口被害を定義する。

---

## 2. 対象

Sprint 6で扱う対象は以下。

```text
- 内部兵数の算出
- 基本ユニット数の算出
- 基本ユニットのスタック数算出
- 特殊ユニット拡張方針
- 防衛突破時の人口被害
- 人口下限との整合
- 戦闘ログ・人口被害ログ
```

---

## 3. 前提

### 3.1 既存実装済み仕様

以下は既存実装済み前提とする。

```text
- 兵力のユニット変換
- 戦闘での兵力消費
- 人手システム
- 人口を稼働と作業に分けてあてがう仕様
```

Sprint 6では、既存実装を上書きせず、人口・満足度から算出する内部兵数とユニット生成ロジックを整理する。

---

### 3.2 人口スケール

人口は内部的には抽象人口値として管理する。

```text
内部人口1 = 1k人
```

表示例：

| 内部人口 | UI表示 |
|---:|---|
| 10 | 10k人 |
| 50 | 50k人 |
| 100 | 100k人 |
| 500 | 500k人 |
| 1000 | 1.0M人 |

---

### 3.3 人口下限

```text
人口下限：
内部人口10
```

UI表示：

```text
10k人
```

人口は、防衛突破による即時人口減少でも人口下限を下回らない。

### 3.4 満足度段階

満足度段階は、Sprint 4で定義済みの5段階を使用する。

```text
- 衰退
- 不満
- 安定
- 満足
- 繁栄
```

## 4. 用語定義

### 4.1 人口

都市全体の人口規模。

```text
人口：
都市の生活・生産・建築・軍事を支える母体
```

### 4.2 内部兵数

人口と満足度から算出される、動員可能な兵数の内部値。

```text
内部兵数：
人口と満足度から算出されるユニット生成用の内部値
```

内部兵数は、人口そのものではない。  
内部兵数は、出撃可能な軍事動員力を表す。

### 4.3 兵力

戦闘に投入可能な軍事力概念。

```text
兵力：
内部兵数・装備・練度・士気などを含む軍事力概念
```

### 4.4 ユニット

攻城戦盤面に出す戦闘単位。

```text
ユニット：
攻城戦盤面に表示・配置される戦闘単位
```

ユニットは人口と直接換算しない。  
ユニットは、兵士数そのものではなく、攻城戦上の戦闘単位として扱う。

---

## 5. 内部兵数の算出

### 5.1 基本式

```text
内部兵数 = floor(内部人口 × 基礎動員率 × 満足度段階補正)
```

### 5.2 基礎動員率

```text
基礎動員率 = 8%
```

計算上は以下を使う。

```text
0.08
```

### 5.3 満足度段階補正

| 満足度段階 | 兵数補正 |
|---|---:|
| 衰退 | 0.50 |
| 不満 | 0.75 |
| 安定 | 1.00 |
| 満足 | 1.10 |
| 繁栄 | 1.25 |

### 5.4 計算例

内部人口1000・繁栄の場合：

```text
内部兵数 = floor(1000 × 0.08 × 1.25)
= floor(100)
= 100
```

## 6. 人口ごとの基本ユニット数

安定時の見え方は以下。

| 内部人口 | UI人口 | 基本ユニット数 | 必要スタック数 |
|---:|---|---:|---:|
| 50 | 50k人 | 4 | 2 |
| 100 | 100k人 | 8 | 3 |
| 250 | 250k人 | 20 | 7 |
| 500 | 500k人 | 40 | 14 |
| 750 | 750k人 | 60 | 20 |
| 1000 | 1.0M人 | 80 | 27 |

人口1.0M・繁栄時：

```text
内部兵数 = floor(1000 × 0.08 × 1.25)
= 100
```

```text
基本ユニット数 = 100
必要スタック数 = ceil(100 / 3) = 34
```

## 7. 基本ユニット生成

### 7.1 基本仕様

MVPでは、内部兵数から基本ユニットのみを生成する。

```text
基本ユニット数 = 内部兵数
```

### 7.2 1ユニット必要兵数

MVPでは、1ユニットに必要な兵数は一律1とする。

```text
1ユニット必要兵数 = 1
```

したがって、

```text
基本ユニット数 = floor(内部兵数 / 1)
```

になる。

### 7.3 人口との直接換算禁止

ユニットは人口と直接換算しない。

```text
ユニット数 ≠ 人口人数
```

ユニットは、攻城戦盤面で扱う戦闘単位であり、人口何人分という扱いにはしない。

---

## 8. スタックルール

### 8.1 最大スタック数

```text
1スタック最大ユニット数 = 3
```

### 8.2 必要スタック数

```text
必要スタック数 = ceil(ユニット数 / 3)
```

例：

```text
ユニット数80
必要スタック数 = ceil(80 / 3) = 27
```

---

## 9. 特殊ユニットの将来拡張方針

Sprint 6 MVPでは、特殊ユニットは実装しない。

ただし、将来追加時に破綻しないよう、特殊ユニットの生成方式は以下の2系統を想定する。

```text
1. 兵数配分型
2. 兵数非依存型
```

---

## 10. 兵数配分型特殊ユニット

### 10.1 定義

兵数配分型は、内部兵数の一部を、建物・偉人・政策・土地タグなどによって特殊ユニットへ変換する方式である。

```text
兵数配分型：
内部兵数の一部を特殊ユニットに変換する
```

### 10.2 例

```text
内部兵数：100
騎兵化率：20%
火薬兵化率：10%

騎兵：20
火薬兵：10
基本ユニット：70
```

### 10.3 想定ユニット

```text
- 騎兵
- 重装兵
- 弓兵
- 火薬兵
```

### 10.4 効果を持たせる対象

```text
- 建物
- 偉人
- 政策
- 土地タグ
- 特殊資源
```

例：

```text
厩舎：
内部兵数の一定割合を騎兵に変換する

鍛冶屋：
内部兵数の一定割合を重装兵に変換する

火薬工房：
硫黄タグなどを条件に、内部兵数の一定割合を火薬兵に変換する
```

---

## 11. 兵数非依存型特殊ユニット

### 11.1 定義

兵数非依存型は、内部兵数とは別枠で、カード・報酬・イベント・召喚・特殊建物効果などから追加生成される方式である。

```text
兵数非依存型：
内部兵数とは別に追加生成されるユニット
```

### 11.2 例

```text
傭兵カードで3体追加
ゴーレム召喚で1体追加
イベント報酬で特殊部隊追加
```

### 11.3 想定ユニット

```text
- 傭兵
- 召喚ユニット
- ゴーレム
- イベント報酬ユニット
```

---

## 12. 特殊ユニットの兵数消費

### 12.1 基本方針

MVPおよび初期拡張では、全ユニットの兵数消費は1で統一する。

```text
全ユニットの兵数消費：
一律1
```

つまり、

```text
基本兵1体 = 兵数1
重装兵1体 = 兵数1
騎兵1体 = 兵数1
火薬兵1体 = 兵数1
```

### 12.2 差別化方針

特殊ユニットは、兵数消費ではなく以下で差別化する。

```text
- 変換条件
- 変換率
- ユニット性能
- スタック上限
- 移動速度
- 攻撃特性
- 必要資源
- 必要建物
- 必要土地タグ
```

例：

```text
重装兵：
兵数消費は1。
鍛冶屋や鉄鉱石条件により基本兵の一部を変換する。
基本兵より高耐久・低速。

騎兵：
兵数消費は1。
厩舎や政策により基本兵の一部を変換する。
基本兵より高速。

火薬兵：
兵数消費は1。
硫黄タグや火薬工房により基本兵の一部を変換する。
基本兵より高火力。
```

## 13. 突撃時の人口減少

### 13.1 基本方針

突撃時に人口は直接減少しない。

```text
突撃時人口減少：
なし
```

### 13.2 理由

```text
- 突撃で消費するのは既存の兵力/ユニット
- 人口まで減らすと二重消費になりやすい
- ユニットと人口を直接換算しない設計と整合する
```

突撃時は、既存の兵力・ユニット消費処理を使用する。

---

## 14. 防衛突破時の人口被害

### 14.1 基本仕様

防衛突破時は、都市被害として人口が即時減少する。

```text
防衛突破時：
突破敵ユニット数に応じて人口が即時減少する
```

### 14.2 計算式

```text
防衛突破人口被害 = 突破敵ユニット数 × 1
```

意味：

```text
敵1ユニット突破 = 内部人口1の都市被害
```

UI上：

```text
敵1ユニット突破 = 1k人規模の都市被害
```

これは敵ユニットの人数ではなく、敵ユニット突破による都市被害として扱う。

### 14.3 人口下限との関係

防衛突破による人口被害でも、人口下限10を下回らない。

```text
population = max(10, population - 防衛突破人口被害)
```

例：

```text
現在人口：18
突破敵ユニット数：12
人口被害：12

通常計算：
18 - 12 = 6

人口下限適用：
max(10, 6) = 10

結果：
人口10で停止
```

## 15. 防衛成功・防衛突破の満足度影響

### 15.1 防衛成功ボーナス

MVPでは、防衛成功による満足値ボーナスは入れない。

```text
防衛成功時の満足度ボーナス：
MVP非対象
```

### 15.2 防衛突破ペナルティ

MVPでは、防衛突破時の満足値ペナルティは入れない。

```text
防衛突破時の満足度ペナルティ：
MVP非対象
```

理由：

```text
- 防衛突破は人口被害だけで十分重い
- 満足度ペナルティまで入れると悪化ループが強くなりすぎる
- まずは人口被害だけで体感を見る
```

## 20. 確定仕様

```text
- 人口・満足度から内部兵数を算出する
- 基礎動員率は8%
- 内部兵数 = floor(内部人口 × 0.08 × 満足度段階補正)
- 満足度補正は、衰退0.50 / 不満0.75 / 安定1.00 / 満足1.10 / 繁栄1.25
- 基本ユニット数 = 内部兵数
- 1ユニット必要兵数は1
- 1スタック最大ユニット数は3
- 必要スタック数 = ceil(ユニット数 / 3)
- MVPでは基本ユニットのみ実装する
- 将来の特殊ユニットは、兵数配分型と兵数非依存型の2系統を想定する
- 全ユニットの兵数消費は初期拡張では一律1とする
- 特殊ユニットは、兵数消費ではなく変換条件・変換率・性能・スタック上限などで差別化する
- 突撃時に人口は直接減少しない
- 突撃時は既存の兵力/ユニット消費処理を使用する
- 防衛突破時のみ人口が即時減少する
- 防衛突破人口被害 = 突破敵ユニット数 × 1
- 防衛突破は敵ユニットの人数ではなく、都市被害として扱う
- 人口下限10を下回らない
```
