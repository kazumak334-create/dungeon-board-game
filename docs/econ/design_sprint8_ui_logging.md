# Sprint 8：UI・ログ・デバッグ企画書 確定版

Sprint 8では、報酬UI・土地カード報酬UI・宝箱UI・次ゲーム遷移は扱わない。  
これらは次Sprint対象とする。

## 4. 常時表示UI

### 4.1 表示項目

常時表示UIでは、都市状態の判断に必要な最低限の情報だけを表示する。

```text
常時表示UI：
- 人口
- 食料値
- 満足度段階
- 兵力
- 兵数
- ユニット数
```

### 4.2 表示例

```text
人口：150k / 250k
食料値：24
満足度：満足
兵力：88
兵数：80
ユニット：80
```

---

## 5. 人口表示

人口は、`k` / `M` 単位で表示する。  
末尾に「人」は付けない。

```text
内部人口50 → 50k
内部人口100 → 100k
内部人口1000 → 1.0M
```

表示例：

```text
人口：150k / 250k
```

---

## 6. 満足度表示

### 6.1 常時表示

常時表示では、満足度段階のみを表示する。

```text
満足度：満足
```

常時表示では以下を表示しない。

```text
- 満足値%
- 満足値傾き
- 満足値傾き内訳
```

これらは満足度詳細ポップアップで表示する。

### 6.2 満足度詳細ポップアップ

常時表示UIの「満足度」をタップ/クリックすると、その場に小型ポップアップとして満足度詳細を表示する。

```text
満足度詳細：
- 満足度段階
- 満足値%
- 満足値傾き
- 満足値傾き内訳
```

表示例：

```text
満足度：満足
満足値：64%
満足値傾き：-0.08%/秒

傾き内訳：
基礎満足傾き：+0.03%/秒
人口規模影響：-0.06%/秒
人口増加影響：-0.04%/秒
建築物影響：+0.05%/秒
食料不足ペナルティ：0.00%/秒
合計：-0.02%/秒
```

## 7. 兵力/兵数/ユニット数表示

### 7.1 表示方針

兵力・兵数・ユニット数は、Sprint 6で定義した値を参照する。  
Sprint 8では計算式を再定義しない。

```text
兵力：
Sprint 6で定義した軍事力の目安値

兵数：
Sprint 6で定義した内部兵数

ユニット数：
Sprint 6で定義した基本ユニット数
```

### 7.2 兵力詳細ポップアップ

常時表示UIの「兵力」をタップ/クリックすると、その場に小型ポップアップとして兵力詳細を表示する。

表示内容：

```text
兵力：88

ユニット数：80

```

補正を表示できる場合は、以下も表示する。

```text

兵舎補正：+10%
その他補正：なし
```

## 8. 詳細UIの基本方針

詳細UIは、右側パネルやボトムシートではなく、その場で開く小型ポップアップにする。

```text
詳細UI：
対象をタップ/クリックした位置の近くに表示する小型ポップアップ
```

### 8.1 共通挙動

```text
- 対象をタップ/クリックすると開く
- 画面外にはみ出す場合は、表示位置を画面内に補正する
- 別対象をタップ/クリックすると内容を切り替える
- 何もない場所をタップ/クリックすると閉じる
```

## 10. 共通建物進捗UI

### 10.1 基本方針

タイマー/進捗を持つ建物は、すべて共通の建物進捗UIを使う。

```text
対象：
- 周期発動建物
- 累計条件型建物
- 条件進捗型建物
```

交換所などの累計条件型建物も、この共通仕様に含める。  
個別UIとして外出ししない。

---

### 10.2 BPB風クールダウン表現

建物進捗UIは、BPB風のクールダウン表現を参考に、建物アイコン上へ進捗率を重ねて表示する。

```text
建物進捗UI：
建物アイコン上へ進捗率を視覚的に重ねて表示する
```

MVPでは以下を採用する。

```text
MVP表現：
建物アイコンに、下から上へ進むハイライト/マスクを重ねる
```

---

### 10.3 進捗表示

```text
進捗0%：
建物アイコンは通常または暗め

進捗50%：
建物アイコンの下半分程度がハイライトされる

進捗100%：
建物アイコン全体がハイライトされ、効果を発動する
```

---

### 10.4 実装方針

```text
- 建物Sprite本体は変更しない
- 進捗表示用のOverlay/Maskを建物Sprite上に重ねる
- Overlayの表示高さを progress_rate に応じて変更する
- progress_rate は 0.0〜1.0 で管理する
- 効果発動時に、Overlayを100%表示したうえで発光演出を再生する
- 発動後、progress_rate を0に戻す
```

---

### 10.5 周期発動建物の進捗率

```text
進捗率 = 経過時間 / 現在発動間隔
```

```text
progress_rate = clamp(elapsed_time / current_interval, 0.0, 1.0)
```

対象例：

```text
- 農村
- 森小屋
- 採掘所
- 食堂
- 製粉所
```

---

### 10.6 累計条件型建物の進捗率

```text
進捗率 = 現在累計値 / 必要累計値
```

```text
progress_rate = clamp(current_accumulated_value / required_value, 0.0, 1.0)
```

対象例：

```text
- 交換所
- 将来の累計条件型建物
```

---

### 10.7 発動時演出

進捗100%で効果が発動する。

```text
発動時：
- 建物アイコンを短時間発光させる
- 効果アイコンを短時間発光させる
- 必要に応じて出力資源アイコンを短時間表示する
```

例：

```text
食堂発動：
小麦-1
食料値+2
→ 食料値アイコンが光る
```

## 11. 建物停止理由UI

### 11.1 基本仕様

資源不足・人手不足で建物が稼働できない場合、タイマー/進捗は停止する。

```text
停止中：
- 進捗率を保持
- ハイライト状態を保持
- 停止理由を吹き出しで表示
```

### 11.2 吹き出し表示

```text
人手不足：
人アイコン + ❌

資源不足：
対象資源アイコン + ❌
```

例：

```text
小麦 ❌
人手 ❌
石 ❌
```

複数不足している場合は、複数アイコンを表示する。

## 13. ログ出力

```text
- 満足度ログ

- 資源獲得ログ
- 兵力/兵数/ユニットログ

```

## 14. デバッグ操作

MVP検証用に、以下の操作を用意する。

```text
- 資源を追加する
- 食料値を追加する
- 人口を追加する
- 人口上限を追加する
- 満足値を変更する
- 満足度段階を疑似変更する
- 建物進捗を強制的に進める
- 疑似防衛突破を発生させる
```

目的：

```text
- 人口1000到達検証
- 食料不足時の挙動確認
- 満足度悪化時の挙動確認
- 建物停止UI確認
- 建物進捗UI確認
- 兵力/兵数/ユニット表示確認
- 防衛突破人口被害確認
```

## 16. 確定仕様

```text
- Sprint 8は都市状態・建物稼働・進捗表現・ログ・デバッグ可視化に集中する
- 報酬UI・土地カード報酬UI・宝箱UI・次ゲーム遷移は次Sprint対象にする
- 常時表示UIには、人口・食料値・満足度段階・兵力・兵数・ユニット数を表示する
- 人口表示は「人口：150k / 250k」とし、「人」は付けない
- 常時表示UIでは満足値%と満足値傾きは表示しない
- 満足度詳細は、満足度項目をタップ/クリックして小型ポップアップで表示する
- 兵力詳細は、兵力項目をタップ/クリックして小型ポップアップで表示する
- 建物詳細は、建物をタップ/クリックして建物付近の小型ポップアップで表示する
- 右側詳細パネル・ボトムシートは使わない
- タイマー/進捗を持つ建物は、すべて共通の建物進捗UIを使う
- 建物進捗UIは、BPB風のクールダウン表現を参考に、建物アイコン上へ進捗率を重ねて表示する
- MVPでは、建物アイコンに下から上へ進むハイライト/マスクを重ねる方式を採用する
- 周期発動建物は、経過時間/現在発動間隔で進捗率を算出する
- 累計条件型建物は、現在累計値/必要累計値で進捗率を算出する
- 進捗100%で効果発動し、建物または効果アイコンを短時間発光させる
- 停止中は進捗率とハイライト状態を保持し、停止理由アイコンを吹き出しで表示する
- 資源不足/人手不足時は、対象アイコン＋❌で停止理由を表示する
- 建物詳細ポップアップで足元土地情報を表示する
- 人口・食料値・満足度・建物稼働・資源獲得・兵力/兵数/ユニット・防衛突破ログを出力する
- MVP検証用のデバッグ操作を用意する
```

## 17. 残論点

Sprint 8の主要仕様は確定済みとする。  
以下はテストプレイ調整項目として扱う。

```text
- 常時表示UIの情報量が多すぎないか
- 兵力/兵数/ユニット数の3つを常時表示して分かりづらくないか
- 小型ポップアップが盤面視認性を阻害しないか
- 建物進捗Overlay/Maskが視認しやすいか
- 停止理由吹き出しが多すぎて画面がうるさくならないか
- デバッグ操作がMVP検証に十分か
```
