### 4. プレイテストパターン（5パターン必須）

#### パターン A: 最適化（効率的成長）
**目標:** リソースを効率的に配分して都市を成長させる

**プレイフロー:**
1. 初期リソースで基本施設配置
2. リソース生産を最大化するボーナス施設を優先建築
3. ユニットを段階的に配置
4. バトルで兵力化

**検証項目:**
- [ ] リソース生産が単調増加している
- [ ] 施設ボーナスが正しく計算されている
- [ ] ユニット配置が正常に進行している
- [ ] バトル時に兵力が正しく反映されている

**ログ確認:**
```
1. リソース生産速度の増加傾向を確認
2. 施設建築による生産ボーナス計算確認
3. ユニット配置イベントの記録確認
4. バトル前後のリソース/ユニット変化確認
```

---

#### パターン B: 詰まり（リソース枯渇）
**目標:** リソース計画の失敗で都市が詰まる状況を再現

**プレイフロー:**
1. 初期リソースで施設を建築しすぎる
2. 生産量が消費量に追いつかない
3. リソース枯渇に至る
4. 新規建築ができなくなる

**検証項目:**
- [ ] リソースが段階的に減少している
- [ ] 建築ボタンが無効化される（リソース不足表示）
- [ ] UI警告が赤く変化している
- [ ] ログに「リソース不足」イベントが記録されている

**ログ確認:**
```
1. リソース減少速度が生産速度を上回る時点を特定
2. 詰まり開始時刻をタイムスタンプで確認
3. UI警告表示の発生タイミングを確認
```

---

#### パターン C: 危機→回復
**目標:** リソース枯渇から回復する過程を再現

**プレイフロー:**
1. リソース枯渇の状況に陥る（パターン B）
2. 施設の一部を破壊して消費を削減
3. リソース生産が消費を上回る状態に戻す
4. 段階的に施設を再建築

**検証項目:**
- [ ] 施設破壊によるリソース回復が計算されている
- [ ] リソース生産が消費を上回る時点を特定できる
- [ ] UI警告が赤から通常に戻っている
- [ ] ログに「施設破壊」「リソース回復」イベントが記録されている

**ログ確認:**
```
1. 詰まり→回復の折り返し時刻を特定
2. 施設破壊によるリソース回復量を確認
3. リソース収支の転換点をグラフ化
```

---

#### パターン D: 兵力化
**目標:** 都市資源をユニット配置に投入してバトルに進む

**プレイフロー:**
1. 施設で安定的にリソースを生産
2. 大量のユニットを配置
3. バトルに進む
4. ユニット喪失によるリソース低下を確認

**検証項目:**
- [ ] ユニット配置がリソースを正しく消費している
- [ ] 配置ユニット数がバトルデッキに正しく反映されている
- [ ] バトル後のユニット喪失がリソース表示に反映されている
- [ ] ログに「ユニット配置」「バトル開始」「ユニット喪失」が記録されている

**ログ確認:**
```
1. バトル前のユニット配置数確認
2. バトル後のユニット喪失数確認
3. リソース再生産の開始時点確認
```

---

#### パターン E: 失敗（回復不可）
**目標:** リソース枯渇から回復不可能な状況を再現

**プレイフロー:**
1. 初期リソースをすべて消費する施設を建築
2. 生産施設なしで詰まる
3. 回復手段がない（施設破壊してもリソースが増えない）
4. ゲーム進行不可能状態に陥る

**検証項目:**
- [ ] ゲーム進行不可能な状態を定義できている
- [ ] UI上でそれが明示的に表示されている
- [ ] ログに「ゲーム失敗」または「進行不可能」が記録されている
- [ ] このパターンで「リスタート」オプションが表示される

**ログ確認:**
```
1. 失敗判定のロジックが正しく動作
2. UI警告の最終段階が表示される
3. ゲーム終了時のログが正しく生成される
```
