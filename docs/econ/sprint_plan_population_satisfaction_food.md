# スプリント計画書：人口・満足度・食料値システム反映版

## 1. 目的

本スプリントでは、既存のパネル・建物・資源システムに対して、人口・満足度・食料値の都市ステータス管理を組み込む。

本計画は、以下を実装・検証するためのスプリント計画である。

- 小麦と食料値の分離
- 食料値による人口維持・人口定着コストの導入
- 人口のリアルタイム増減
- 満足値・満足値傾きによる満足度管理
- 満足度5段階による人口・兵力・建物効率補正
- 突撃・防衛突破による即時人口減少
- 初期デッキへの食堂追加
- 序盤カードプールへの製粉所追加

---

## 2. 前提

本ゲームはターン制ではなく、リアルタイム進行である。

ただし、すべてを完全な連続処理にするのではなく、以下の方式で扱う。

| 要素 | 処理方式 |
|---|---|
| 人口 | リアルタイムに増減 |
| 満足値 | リアルタイムに変化 |
| 満足値傾き | リアルタイムに再計算 |
| 満足度段階 | 満足値%からリアルタイムに算出 |
| 食料値獲得 | 建物ごとの周期発動 |
| 食料値消費 | 周期処理・人口増加確定時 |
| 突撃人口消費 | 即時処理 |
| 防衛突破人口被害 | 即時処理 |

---

小麦は人口を直接増やさない。  
小麦は食堂・製粉所・レストランなどで消費され、食料値や小麦増加効果につながる原材料である。

### 3.3 都市ステータス

class_name CityStatus

### 完了条件

## 6. Sprint 2：食料値システムの実装

### 目的

小麦を直接人口に接続せず、食料値を経由して人口維持・人口定着に接続する。

### 食料値の定義

食料値は都市ステータスである。

食料値は以下に使用する。

- 人口維持
- 人口増加確定時の定着コスト

### 実装対象

- 食料値加算処理
- 食料値消費処理
- 食料不足カウント
- 食堂
- 製粉所

---

### 6.1 食堂

食堂は初期デッキに入れる。

#### 仕様

| 項目 | 内容 |
|---|---|
| 分類 | 建物 / 都市ステータス生成施設 |
| 初期デッキ | 採用 |
| 発動トリガー | 周期発動 |
| 発動間隔 | 5秒 |
| 通常効果 | 小麦1を消費して食料値+2 |
| 香辛料タグ効果 | 足元パネルに香辛料タグがある場合、食料値+3 |
| 小麦不足時 | 発動しない |

#### 実装内容

- 5秒ごとに発動する
- 小麦が1以上ある場合、小麦を1消費する
- 食料値を加算する
- 足元パネルに香辛料タグがある場合、食料値加算量を3にする
- 小麦不足時はログを出して発動しない

---

### 6.2 製粉所

製粉所は採用する。  
ただし、初期デッキではなく序盤カードプールに入れる。

#### 仕様

| 項目 | 内容 |
|---|---|
| 分類 | 建物 / 加工施設 |
| 初期デッキ | 不採用 |
| 序盤カードプール | 採用 |
| 発動トリガー | 周期発動 |
| 発動間隔 | 5秒 |
| 通常効果 | 小麦1を消費して小麦+2 |
| 小麦パネル効果 | 足元パネルの小麦値が3以上なら追加で小麦+1 |
| 小麦不足時 | 発動しない |

#### 通常時

- 小麦-1
- 小麦+2
- 差し引き小麦+1

#### 足元パネル小麦3以上

- 小麦-1
- 小麦+3
- 差し引き小麦+2

---

### 6.3 人口維持処理

人口維持処理は、リアルタイム上で5秒ごとに発動する周期処理である。

#### 仕様

```text
維持必要食料値 = floor(現在人口)
最低値 = 1
```

#### 食料値が足りる場合

- 維持必要食料値ぶん食料値を消費する
- 食料不足カウントを1減らす
- 食料不足カウントの最低値は0

#### 食料値が不足する場合

- 残っている食料値をすべて消費する
- 食料不足カウント+1
- 食料値不足状態として扱う

### 完了条件

- 食堂が5秒ごとに食料値を生成できる
- 香辛料タグ上の食堂が食料値+3を生成できる
- 製粉所が小麦ブースト施設として動く
- 人口維持処理が5秒ごとに発動する
- 食料不足カウントが増減する
- 食料値不足状態をログ出力できる

---

## 7. Sprint 3：人口システムの実装

### 目的

人口をリアルタイムに増減する都市ステータスとして実装する。

### 人口の定義

人口は以下の性質を持つ。

- 内部的には小数で管理する
- UI上は整数表示する
- 人口変化量によってリアルタイムに増減する
- 1未満にならない
- 人口上限を超えない

### 表示人口

```text
表示人口 = floor(現在人口)
最低値 = 1
```

---

### 7.1 人口上限

人口上限は、住宅などで決まる物理的な受け入れ上限である。

実効人口上限は使用しない。

人口上限に到達している場合、人口増加要因は0として扱う。

---

### 7.2 人口変化量

人口変化量は、複数の人口増加要因と人口減少要因の合算で算出する。

```text
人口変化量 = 人口増加要因合計 - 人口減少要因合計
```

人口変化量が正の場合、人口は増える。  
人口変化量が負の場合、人口は減る。  
人口変化量が0の場合、人口は維持される。

---

### 7.3 人口増加要因

MVPでは、満足度段階を主な人口増加要因とする。

| 満足度段階 | 人口増加要因 |
|---|---:|
| 衰退 | +0.00 人口/秒 |
| 不満 | +0.00 人口/秒 |
| 安定 | +0.02 人口/秒 |
| 満足 | +0.04 人口/秒 |
| 繁栄 | +0.05 人口/秒 |

人口が人口上限に到達している場合、人口増加要因は0とする。

---

### 7.4 人口減少要因

MVPで採用するリアルタイム人口減少要因は以下。

- 食料値不足
- 不満
- 衰退

| 減少要因 | 人口減少要因 |
|---|---:|
| 食料値不足 | -0.04 人口/秒 |
| 不満 | -0.04 人口/秒 |
| 衰退 | -0.10 人口/秒 |

食料値不足と不満/衰退は加算されうる。

例：

```text
不満 かつ 食料値不足：
人口変化量 = 0.00 - 0.04 - 0.04 = -0.08 人口/秒
```

---

### 7.5 人口増加確定処理

人口は小数で増える。  
次の整数人口に到達するタイミングで、人口増加確定処理を行う。

#### 仕様

```text
人口増加必要食料値 = floor(現在人口)
最低値 = 1
```

繁栄時：

```text
人口増加必要食料値 = max(1, floor(現在人口) - 1)
```

#### 食料値が足りる場合

- 人口増加必要食料値ぶん食料値を消費する
- 次の整数人口への到達を確定する

#### 食料値が不足する場合

- 人口増加を確定しない
- 食料値が足りるまで次の整数人口に到達しない

### 完了条件

- 人口が人口変化量に応じてリアルタイムに増減する
- 人口上限で増加が止まる
- 食料値不足時に人口減少要因が加算される
- 不満/衰退時に人口減少要因が加算される
- 整数人口到達時に食料値を消費できる
- 食料値不足時に人口増加確定が止まる
- 人口変化量の内訳をログ出力できる

---

## 8. Sprint 4：満足度システムの実装

### 目的

都市全体の状態を、満足値・満足値傾き・満足度段階で管理する。

### 満足値

満足値は0〜100%で管理する。

```text
初期満足値 = 60%
```

### 満足値傾き

満足値傾きは、満足値が時間経過で増減する速度である。

```text
満足値 = 満足値 + 満足値傾き × 経過秒数
```

満足値は0〜100%にクランプする。

---

### 8.1 満足値傾きの式

```text
満足値傾き =
基礎傾き
+ 人口規模影響
+ 人口変化量影響
+ 建築物影響
+ 政策影響
+ 特殊タグ影響
- 食料不足ペナルティ
- その他ペナルティ
```

MVPで使う項目：

- 基礎傾き
- 人口規模影響
- 人口変化量影響
- 建築物影響
- 食料不足ペナルティ

将来拡張：

- 政策影響
- 特殊タグ影響
- その他ペナルティ

---

### 8.2 基礎傾き

```text
基礎傾き = 0%/秒
```

---

### 8.3 人口規模影響

人口が多いこと自体による恒常的な満足値傾き補正である。

初期仮置き：

| 現在人口 | 人口規模影響 |
|---:|---:|
| 1〜2 | +0.02%/秒 |
| 3〜4 | 0%/秒 |
| 5〜6 | -0.03%/秒 |
| 7〜9 | -0.06%/秒 |
| 10以上 | -0.10%/秒 |

---

### 8.4 人口変化量影響

人口が増加している状態による一時的な満足値傾き補正である。

初期仮置き：

```text
人口変化量影響 = 人口増加速度 × -1.0
```

例：

```text
人口変化量 +0.04 人口/秒
→ 満足値傾き -0.04%/秒
```

人口減少中は、MVPでは補正なしとする。

---

### 8.5 建築物影響

建築物影響は、満足値傾きに加算される建築物由来の補正である。

初期仮置き：

| 建物 | 建築物影響 |
|---|---:|
| 広場 | +0.05%/秒 |
| レストラン | 稼働中 +0.10%/秒 |
| 市場 | +0.05%/秒 |
| 香辛料市場 | 香辛料タグ付きパネル上なら +0.15%/秒 |

食堂は満足値傾きに直接影響しない。

---

### 8.6 食料不足ペナルティ

```text
食料不足ペナルティ = 食料不足カウント × 0.20%/秒
```

満足値傾きの式ではマイナス項目として扱う。

例：

```text
食料不足カウント2：
満足値傾き -0.40%/秒
```

---

### 8.7 満足度段階

満足値%から以下の5段階を算出する。

| 満足値 | 満足度段階 |
|---:|---|
| 0〜19% | 衰退 |
| 20〜39% | 不満 |
| 40〜59% | 安定 |
| 60〜79% | 満足 |
| 80〜100% | 繁栄 |

### 完了条件

- 満足値がリアルタイムに変化する
- 満足値傾きが複数項目から算出される
- 満足値%から満足度段階を算出できる
- 食料不足カウントが満足値傾きに反映される
- 人口規模影響が満足値傾きに反映される
- 人口変化量影響が満足値傾きに反映される
- 建築物影響が満足値傾きに反映される
- 満足値傾きの内訳をログ出力できる

---

## 9. Sprint 5：満足度段階効果の実装

### 目的

満足度段階が、人口・兵力・建物効率に影響するようにする。

### 満足度段階別効果

| 段階 | 人口 | 兵力 | 建物効率 |
|---|---|---|---|
| 衰退 | 人口増加速度0 / 人口減少速度-0.10 | 兵力獲得なし / 兵力効果-20% | 全建物効率-30% |
| 不満 | 人口増加速度0 / 人口減少速度-0.04 | 兵力獲得量-20% / 兵力効果-10% | 全建物効率-10% |
| 安定 | 人口増加速度+0.02 | 補正なし | 補正なし |
| 満足 | 人口増加速度+0.04 | 兵力獲得量+10% | 全建物効率+5% |
| 繁栄 | 人口増加速度+0.05 / 人口増加必要食料値-1 | 兵力獲得量+20% / 兵力効果+10% | 全建物効率+10% |

### 兵力定義

#### 兵力獲得量

兵舎・訓練所・徴兵所などが新たに得る兵力の量。

#### 兵力効果

保有兵力が戦闘・防衛・攻撃力などに変換される際の有効倍率。

### 建物効率定義

建物効率は、建物出力にかかる全体補正である。

対象候補：

- 資源獲得量
- 食料値獲得量
- 加工施設の出力
- 兵力獲得量

### 完了条件

- 満足度段階によって人口増加/減少速度が変わる
- 満足度段階によって兵力獲得量が補正される
- 満足度段階によって兵力効果が補正される
- 満足度段階によって建物効率が補正される
- 各補正値をデバッグ表示できる

---

## 10. Sprint 6：突撃・防衛人口減少の実装

### 目的

戦闘行動・防衛失敗が人口に影響するようにする。

---

### 10.1 突撃による人口消費

突撃は、都市人口を戦闘ユニットとして送り出す行動である。

#### 仕様

- 突撃ユニット1体につき人口-1
- 人口は最低1を下回らない
- 突撃可能ユニット数は現在人口-1を上限とする
- 突撃人口消費は即時処理
- 人口変化量とは別枠で扱う

---

### 10.2 防衛突破による人口被害

防衛突破は、敵ユニットが防衛を突破して都市へ到達することである。

#### 仕様

- 防衛突破した敵ユニット1体につき人口-1
- 人口は最低1を下回らない
- 防衛人口被害は即時処理
- 人口変化量とは別枠で扱う

### 完了条件

- 突撃時にユニット数ぶん人口が即時減少する
- 人口1未満にならない
- 現在人口-1を超える突撃ができない
- 防衛突破時に突破ユニット数ぶん人口が即時減少する
- 突撃・防衛人口減少ログが出る

---

## 15. 完了条件まとめ

本スプリント群の完了条件は以下。

- 小麦と食料値が別管理になっている
- 食料値が都市ステータスとして管理されている
- 食堂が初期デッキに入っている
- 食堂が小麦を食料値に変換できる
- 製粉所が序盤カードプールに入っている
- 製粉所が小麦ブースト施設として動作する
- 人口が小数で管理され、リアルタイムに増減する
- 人口変化量が増加要因・減少要因の合算で算出される
- 食料値不足が人口減少要因になる
- 満足値が0〜100%で管理される
- 満足値傾きが複数要因から算出される
- 満足度段階が5段階で算出される
- 満足度段階が人口・兵力・建物効率に影響する
- 突撃時に人口が即時減少する
- 防衛突破時に人口が即時減少する
- 人口変化量ログが出る
- 満足値傾きログが出る
