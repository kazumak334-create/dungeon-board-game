# Agent 定義品質チェックリスト

## 背景
2026-04-19: Architect が要件定義書を更新できない問題が発生。
原因：Agent 定義に Edit tool が含まれていなかった。

## Agent 定義時の必須チェック項目

### 1. 責務とツールセットの整合性

| 責務 | 必要なツール | 理由 |
|------|-------------|------|
| ファイル新規作成 | Write | 新規ドキュメント作成 |
| ファイル修正 | Edit | 既存ドキュメント更新 |
| ファイル調査 | Read, Glob, Grep | 既存コード・ドキュメント確認 |
| コマンド実行 | Bash | ビルド・テスト・Git操作 |

### 2. ドキュメント編集を行う Agent

以下の Agent は **必ず Edit tool を含める**：

- **Architect**: 要件定義書の作成・修正
- **Designer**: UI/UX 企画書の作成・修正
- **Planning**: ゲーム仕様書の作成・修正
- **PMO**: roadmap.md, CHANGELOG.md の更新

**必須ツールセット**: `[Read, Write, Edit, Glob, Grep]`

### 3. コード編集を行う Agent

- **Implementer**: 実装ファイル（scripts/*.gd）の編集
- **Checker**: 実装ファイルの修正

**必須ツールセット**: `[Read, Edit, Bash, Glob, Grep]`

### 4. 実行系 Agent

- **PMO**: roadmap 更新 + Git 操作
- **Implementer**: 実装 + 構文チェック

**必須ツールセット**: `[Read, Edit, Bash, Glob, Grep]`

### 5. 禁止事項の明確化

「やらないこと」セクションで以下を明確にする：

- ❌ **実装コードの編集禁止**（設計系 Agent）
  - 例: `scripts/*.gd 等の実装ファイルは編集しない`
- ❌ **要件定義書の編集禁止**（実装系 Agent）
  - 例: `docs/design/*.md は編集しない（参照のみ）`

**間違った書き方（矛盾）**:
```yaml
tools: [Read, Write, Edit, Glob, Grep]
---
## やらないこと
- Edit/Write 禁止  ← ツールセットと矛盾！
```

**正しい書き方**:
```yaml
tools: [Read, Write, Edit, Glob, Grep]
---
## やらないこと
- 実装コードの編集（scripts/*.gd は編集しない）
- コード実行（Bash 禁止）
```

## Agent 定義作成・修正時の手順

1. **責務を明確にする**
   - このAgentは何をするのか？
   - ファイルを作成するのか、修正するのか、参照だけか？

2. **必要なツールをリストアップ**
   - 新規作成 → Write
   - 修正 → Edit
   - 参照 → Read, Glob, Grep
   - 実行 → Bash

3. **ツールセットを定義**
   - `tools: [...]` に必要なツールを全て含める

4. **禁止事項を明確にする**
   - 何を**しない**のかを具体的に書く
   - ツールセットと矛盾しないようにする

5. **完了定義を書く**
   - どうなったら完了なのか明確にする

## 過去の失敗例と修正

### 失敗例 1: Architect（2026-04-19）

**問題**:
```yaml
tools: [Read, Write, Glob, Grep]  ← Edit がない
---
## やらないこと
- 実装（Edit/Write/Bash禁止）  ← ツールセットと矛盾
```

**修正**:
```yaml
tools: [Read, Write, Edit, Glob, Grep]  ← Edit 追加
---
## やらないこと
- 実装コードの編集（scripts/*.gd は編集しない）
- コード実行（Bash 禁止）

## やること（明確化）
- 要件定義書の新規作成（Write）
- 要件定義書の修正（Edit）
```

### 失敗例 2: PMO（過去）

**問題**:
```yaml
tools: [Read, Bash, Glob, Grep]  ← Edit がない
```

**影響**:
- roadmap.md 更新で Bash + sed を使用
- 非効率（41,124 トークン消費）

**修正**:
```yaml
tools: [Read, Edit, Bash, Glob, Grep]  ← Edit 追加
```

**効果**: 60-70% トークン削減（推定 15,000 トークン）

## チェックリスト

新規 Agent 作成時、または既存 Agent 修正時に以下を確認：

- [ ] 責務が明確に定義されている
- [ ] 責務に必要なツールが全て含まれている
- [ ] ツールセットと「やらないこと」が矛盾していない
- [ ] ファイル編集が必要なら Edit tool が含まれている
- [ ] ファイル新規作成が必要なら Write tool が含まれている
- [ ] コマンド実行が必要なら Bash tool が含まれている
- [ ] 「やること」「やらないこと」が具体的に書かれている
- [ ] 完了定義が明確

### 失敗例 3: Architect（2026-04-19 #2）

**問題**:
- Architect に Write tool があるのに使用せず
- 要件定義書の内容を報告したが、実際にファイルを作成しなかった
- Read×4, Grep×1 で 43,780 トークン消費（無駄）

**原因**:
- 完了定義が曖昧：「要件定義書が完成」→「内容を報告」と解釈
- CEOが完了確認を怠った（ファイル存在確認せず）

**修正**:
```yaml
## 完了定義
- **要件定義書ファイルが実際に存在する**（Write/Editツール使用必須）
- 要件定義書の内容が完成している
- CEOの承認を得た（企画意図と合致しているか）

## 完了報告必須項目
- ✅ Writeツール使用（新規作成時）
- ✅ Editツール使用（修正時）
- ✅ ファイルパスと作成/修正箇所を明記
```

**CEOの対応**:
- Architect応答後、必ず `ls` または `git diff` でファイル存在確認
- ファイルが存在しない場合、即座にArchitectに再指示
- 確認せずに次のステップに進まない

**効果**: トークン無駄遣い防止（43,780 → 0）

## トークン節約の原則

### 該当箇所だけを修正（ファイル全体読み込み禁止）

**悪い例**:
- Architectが4ファイル全部読み込み（Read×4）
- 不要な調査で43,780トークン消費
- 結果：ファイル作成せず

**良い例**:
- 該当セクションのみ読み込み（Read×1、offsetとlimitを使用）
- 必要最小限の調査
- すぐにWrite/Edit実行

### CEOのプロンプト作成ルール

**必須項目**:
```
`docs/design/XX.md`の§N.N（該当箇所のみ）に反映せよ。

**制約**:
- 該当セクションのみ修正（他セクションは読むな）
- 必ずWrite/Editツールを使用
```

**禁止事項**:
- ❌ 「ファイル全体を見直して」
- ❌ 「詳しく調査して」
- ❌ 制約を明記しない曖昧な指示
