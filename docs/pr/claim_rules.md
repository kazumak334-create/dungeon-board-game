# PR発信 表現ルール

作成日: 2026-04-23
用途: PR Agentが誇張・虚偽・炎上リスクを避けるためのガードレール

---

## 禁止表現

以下の表現は**使用禁止**。理由と代替表現を併記。

| 禁止表現 | 理由 | 代替表現 |
|---|---|---|
| 「革新的」「画期的」 | 根拠なき誇張・業界全体の軽視に繋がる | 「〜〜という試み」「独自設計」 |
| 「世界初」「唯一」 | 検証不能な主張 | 「自分が知る限り」「珍しい」 |
| 「最強」「最高」 | 比較対象なき断定 | 「手応えのある」「納得感のある」 |
| 「完成」「完璧」 | 開発中の誤解を招く | 「プレイ可能」「プロトタイプ」 |
| 「すぐリリース」「もうすぐ発売」 | 時期未確定を曖昧化 | 「リリース時期は未定」 |

---

## 要注意表現（使う場合は明確な根拠添付）

- 「〇〇時間遊べる」→ プレイテスト結果に基づくデータがあれば可
- 「盤面が熱い」「脳汁出る」→ 主観表現として明示（「私はそう感じた」等）
- 「〇〇系」→ 比較先が明確な場合のみ（「Slay the Spire系のデッキ構築」等）
- 「簡単」「誰でも」→ 対象層を明示（初心者向けなのか経験者向けなのか）

---

## 実装状況の表現ルール

| 状況 | 推奨表現 |
|---|---|
| 実装済み・テスト済み | 「実装しました」「動きました」 |
| 実装済み・未テスト | 「実装途中」「動き始めた」 |
| 未実装・roadmap登録済み | 「実装予定」「次に作る」 |
| 検討中 | 「検討中」「可能性を探っている」 |
| 廃止済み | 言及しない |

---

## 核体験との整合チェック

発信する前に以下を自問：

- [ ] 「盤面を設計して、介入を仕込んで、答え合わせを観戦する」の体験と一致しているか
- [ ] 3秒ルール違反を誇張していないか（複雑な効果を「シンプル」と書いていないか）
- [ ] 廃止済み設計に言及していないか

---

## トーン配分（通常時）

| 軸 | 比率 |
|---|---|
| ゲーム体験（盤面・戦術・演出） | **70%** |
| 制作裏側（技術・工夫・苦労） | **20%** |
| 開発者成長ストーリー（Git未経験→配信） | **10%** |

※従来は「素人開発ストーリー大切」が主軸だったが、ゲーム体験を主軸にする方針へ転換（2026-04-23 判定）。

---

## 誇張リスク確認ステップ（全投稿必須）

発信文生成後、以下を自己チェック：

1. 禁止表現が入っていないか
2. 実装状況の表現が事実と一致しているか（fact_sheet.mdと突合）
3. 主観表現に「個人の感想」と明示されているか
4. 廃止済み設計に言及していないか
5. 数値・時間等の具体的主張に根拠があるか

このチェックを通過しない投稿文は発信しない。

## ハッシュタグ運用

- 基本セット: `#個人開発 #gamedev #indiegame #ゲーム開発`
- 画像投稿時: `#screenshotsaturday`（土曜のみ）を追加
- 過度な追加は禁止（5タグ以内が目安）
