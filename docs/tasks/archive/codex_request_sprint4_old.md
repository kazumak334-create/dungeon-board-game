## 実装概要

Sprint 4 では、都市の満足度を管理するために、満足値・満足値傾き・満足度段階を実装する。

**核となる仕様:**
- 満足値: 0～100% で管理
- 初期満足値: 60%（「満足」段階から開始）
- 満足値傾き: 毎秒 % で変化（上限・下限なし）
- 基礎満足傾き: +0.03%/秒
- 人口規模影響: 人口により -0.18%～+0.02%/秒
- 人口変化量影響: `max(0, 人口増加速度) × -0.2`
- 食料不足ペナルティ: 食料不足カウント × 0.50%/秒
- 建築物影響: 受け口のみ実装
- 満足度段階: 5段階（衰退/不満/安定/満足/繁栄）

## 実装内容

### 1. 満足度フィールド設定
- `satisfaction_value: float = 60.0` - 初期満足値 60%
- `satisfaction_slope: float = 0.0` - 満足値傾き（%/秒）
- `building_satisfaction_modifier: float = 0.0` - 建築物による満足値傾き補正

### 2. 満足値傾き計算（毎フレーム）
```
満足値傾き = 
  基礎満足傾き（+0.03%/秒）
  + 人口規模影響（表参照）
  + 人口変化量影響（max(0, 人口増加速度) × -0.2）
  + 建築物影響（デフォルト 0）
  - 食料不足ペナルティ（食料不足カウント × 0.50%/秒）
```

### 3. 人口規模影響テーブル
| 内部人口 | UI表示 | 人口規模影響 |
|---:|---|---:|
| 1〜50 | 1k〜50k人 | +0.02%/秒 |
| 51〜100 | 51k〜100k人 | 0%/秒 |
| 101〜250 | 101k〜250k人 | -0.03%/秒 |
| 251〜500 | 251k〜500k人 | -0.06%/秒 |
| 501〜750 | 501k〜750k人 | -0.10%/秒 |
| 751〜1000 | 751k〜1.0M人 | -0.14%/秒 |
| 1001以上 | 1.0M人超 | -0.18%/秒 |

### 4. リアルタイム満足値更新（毎フレーム）
```
満足値 = clamp(満足値 + 満足値傾き × delta, 0, 100)
```

### 5. 満足度段階算出
```gdscript
func get_satisfaction_stage() -> String:
    # 0～19% → "declining" (衰退)
    # 20～39% → "dissatisfied" (不満)
    # 40～59% → "uneasy" (安定)
    # 60～79% → "satisfied" (満足)
    # 80～100% → "thriving" (繁栄)
```

### 6. 人口システムとの接続
満足度段階から取得する人口増加率・減少率（Sprint 3 で使用）:

| 段階 | 増加率 | 減少率 |
|---|---|---|
| 衰退 | 0%/秒 | -0.12%/秒 |
| 不満 | 0%/秒 | -0.04%/秒 |
| 安定 | +0.02%/秒 | 0%/秒 |
| 満足 | +0.04%/秒 | 0%/秒 |
| 繁栄 | +0.06%/秒 | 0%/秒 |

### 7. 建築物影響受け口
- `set_building_satisfaction_modifier(modifier: float)` - 建築物からの満足値傾き補正を受け取る
- 初期値: 0.0
- 複数建築物の補正は合算される

### 8. デバッグログ
- 起動時に「満足度システム初期化完了」ログ
- 任意フレームで現在の満足値傾き内訳をログ出力できる構造
