# effect_id定義の曖昧箇所洗い出し報告

## 総括
- **対象effect_id数**: 30個（新規追加分）
- **曖昧箇所検出数**: 21個
- **主な問題**: 対象・値の具体性不足、常時トリガーの処理タイミング不明、既存システムとの統合未定義

---

## 1. トリガーの曖昧さ（3件）

### heal_reduction_cursed
- **問題**: トリガー「常時」の処理タイミングが不明確
- **詳細**: 回復処理発生時に減少を適用するのか、毎フレーム評価するのかが未定義
- **影響**: 実装方法が複数解釈可能（回復処理側で参照 vs 常時評価フラグ）
- **推奨**: 「回復処理時」または「回復量計算時に参照」と明記

### crit_mult_boost
- **問題**: トリガー「常時」の処理タイミングが不明確
- **詳細**: クリティカル判定時に倍率を参照するのか、毎フレーム再計算するのかが未定義
- **影響**: パフォーマンスとクリティカル計算式の設計に影響
- **推奨**: 「クリティカル判定時に参照」と明記

### mana_generation_trigger
- **問題**: トリガー「召喚時」の発動タイミングが不明確
- **詳細**: 召喚直後か、配置完了後か、初回サポート発動時かが未定義
- **影響**: マナ獲得タイミングがゲームバランスに影響
- **推奨**: 「配置完了時」または「on_summon処理時」と明記

## 総評

**曖昧箇所の主な原因**：
- 「カードごとに異なる」表記による具体性不足（9件）
- 「常時」トリガーの処理タイミング未定義（2件）
- 既存システムとの統合方針未確定（2件）
- 計算式の数式表記不足（4件）

**推奨対応**：
1. カード別パラメータ一覧表の作成（別ドキュメント化）
2. 「常時」トリガーの処理タイミング定義ガイドライン策定
3. 計算式は数式表記を必須化（例：ATK × 0.01 × stacks）
4. 既存システムとの統合方針を優先的に確定

**実装への影響**：
- 現状は暫定値・暫定ロジックで実装済み（動作可能）
- バランス調整時に全カードデータの再確認が必要
- Phase 5実装時にspell_slot_sealの仕様確定が必須
