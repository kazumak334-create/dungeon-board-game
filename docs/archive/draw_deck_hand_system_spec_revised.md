# 企画書：ドロー・山札・手札・捨て札システム仕様 修正版

## 0. 目的

本仕様は、MVPにおけるカードドロー周りの基本仕様を定義する。

対象範囲は以下。

```text
・山札
・手札
・捨て札
・バトル中除外
・初期手札
・ターン開始ドロー
・リロード
・追加ドロー
・山札切れ時の処理
・カード使用後の行き先
・政策カードの一時除外
・偉人カードの盤面配置
・バトル終了時の復帰処理
・手札上限
・引けない/使えない/捨てられないケース
```

本ゲームでは、通常建物カードもデッキに含める。  
そのため、ドロー仕様が曖昧だと、建設・リロード・政策・偉人・報酬カード追加のすべてが破綻する。

---

# 1. カード領域

## 論点

カードをどの領域で管理するか。

## 選択肢

```text
A. 山札 / 手札 / 捨て札 の3領域
B. 山札 / 手札 / 捨て札 / バトル中除外 の4領域
C. 永久除外・保留・廃棄なども含めた多領域管理
```

## 推奨案

MVPでは以下4領域を持つ。

```text
・山札
・手札
・捨て札
・バトル中除外
```

ただし、**バトル中除外は内部処理用の領域**とし、UI上では独立した領域として表示しない。

## 理由

通常建物カードは循環させたい。  
一方で、政策カードや偉人カードは同一バトル中に何度も使えると強すぎる。

そのため、内部的には「同一バトル中に再ドローできない領域」が必要。  
ただし、プレイヤーに「除外領域」を見せるとカードゲーム感が強くなりすぎるため、UIでは見せない。

## 起こりうるシーン

```text
・通常建物カードを使ったあと、もう一度引いて同じ建物を建てたい
・政策カードを使ったあと、同じバトル中に再度引きたくない
・偉人カードを使ったあと、カードとしては再ドローせず、盤面上に偉人として表示したい
・山札が尽きた時に、何をシャッフル対象にするかが必要になる
```

## 処理

```text
山札：
これから引くカードの束。

手札：
現在使用・リロード対象として選べるカード。

捨て札：
使用済み通常建物カード、リロードで捨てたカードが入る。
山札が空になった時にシャッフルされて山札へ戻る。

バトル中除外：
使用済み政策カード・偉人カードが入る内部領域。
同一バトル中は山札へ戻らない。
次バトル開始時にデッキへ戻る。
UI上には表示しない。
```

# 2. 初期手札

## 論点

バトル開始時に何枚カードを持つか。

## 選択肢

```text
A. 初期手札3枚
B. 初期手札5枚
C. 初期手札7枚
```

## 推奨案

```text
初期手札：5枚
```

## 理由

通常建物カードもデッキに含まれるため、初動である程度選択肢が必要。  
ただし、リアルタイム制なので7枚以上は判断量が多すぎる。  
5枚なら、初期開拓ルートを考えるには十分。

## 起こりうるシーン

```text
・初手に資源建物が来ない
・初手に政策/偉人が多い
・初手に建設コストが重いカードが多い
・初期マップに合わない建物カードが多い
```

## 処理

```text
バトル開始時、初期手札5枚を持つ。
ターン1開始時の追加ドローは行わない。
初手事故は、バトル開始後のリロードで緩和する。
MVPではマリガンなし。
```

# 3. 手札上限

## 論点

手札上限を設定するか。

## 選択肢

```text
A. 手札上限なし
B. 手札上限5枚
C. 手札上限7枚
D. 手札上限10枚
```

## 推奨案

```text
手札上限：7枚
```

## 理由

初期手札5枚に対して、追加ドローの余地を持たせたい。  
一方で、手札が増えすぎるとUIが重くなり、リアルタイム制と相性が悪い。  
7枚なら、追加ドローの価値を出しつつ、管理可能な範囲に収まる。

## 起こりうるシーン

```text
・追加ドローしたいが、手札が満杯
・ターン開始ドロー時に手札が7枚
・使えないカードが手札を圧迫している
・手札上限がないと、ドロー効果が強くなりすぎる
```

## 処理

```text
手札が7枚未満：
ドロー可能。

手札が7枚：
ドロー不可。

手札上限時にドロー要求が発生した場合：
カードは引かない。
山札も減らない。
コストも支払わない。
```

UI表示例：

```text
手札上限のためドロー不可
```

# 4. ターン開始ドロー

## 論点

いつ、何枚ドローするか。

## 選択肢

```text
A. バトル開始時に初期手札 + 追加1枚
B. 30秒ごとに1枚
C. 毎ターン複数枚
D. リアルタイムで一定秒ごとにドロー
```

## 推奨案

```text
30秒ごとにターン開始。
各ターン開始時に1枚ドロー。
```

ただし、バトル開始時は初期手札5枚のみ。  
ターン1開始時の追加ドローはなし。

## 理由

1ターン30秒のセミリアルタイム制と合わせやすい。  
30秒ごとのドローは、プレイヤーに「次の判断タイミング」を作れる。  
毎秒ドローや複数枚ドローは忙しすぎる。

## 起こりうるシーン

```text
・30秒経過してターン2に入る
・手札上限でターン開始ドローできない
・山札が空でターン開始ドローが発生する
・最終突撃フェーズに入っている
```

## 処理

```text
バトル開始：
初期手札5枚で開始。

30秒経過：
ターン2開始、1枚ドロー。

60秒経過：
ターン3開始、1枚ドロー。

270秒経過：
ターン10開始、1枚ドロー。

300秒経過：
最終突撃フェーズへ移行。
以後、ターンドローなし。
```

# 5. 山札切れ時の処理

## 論点

ドロー時に山札が空の場合、どうするか。

## 選択肢

```text
A. 捨て札をシャッフルして山札に戻す
B. ドロー失敗にする
C. 山札切れでペナルティを入れる
```

## 推奨案

```text
山札が空なら、捨て札をシャッフルして山札に戻し、その後ドローする。
```

## 理由

通常建物カードを循環させる設計なので、山札切れ時の捨て札シャッフルは必須。  
ペナルティは不要。  
デッキ循環そのものをゲームの基本にする。

## 起こりうるシーン

```text
・通常建物カードを何度も使って山札が尽きる
・リロードを多用して山札が尽きる
・政策/偉人を使ったため、捨て札に戻らないカードがある
・山札も捨て札も空になる
```

## 処理

```text
ドロー要求
↓
山札があるか確認
↓
山札があれば1枚引く
↓
山札が空なら捨て札を確認
↓
捨て札があればシャッフルして山札化
↓
1枚引く
```

山札も捨て札も空の場合：

```text
ドロー失敗。
何も起きない。
```

UI表示：

```text
引けるカードがありません
```

# 6. リロード

## 論点

手札事故をどう緩和するか。

## 選択肢

```text
A. リロードなし
B. 1枚捨てて1枚引く
C. 手札を全部捨てて引き直す
D. コストを払ってサーチする
```

## 推奨案

```text
リロード = 手札1枚を捨て札に送り、山札から1枚引く操作。
リロードクールタイム：5秒。
```

## 理由

基本建物もカード化するため、必要カードが引けないと都市建設が止まりやすい。  
ただし、自由サーチにするとデッキ構築の意味が薄れる。  
1枚交換 + 5秒クールタイムなら、手札事故を緩和しつつ、リアルタイム判断になる。

## 起こりうるシーン

```text
・手札に今使えないカードしかない
・資源不足の建物カードが手札を圧迫している
・政策カードを今使いたくない
・偉人カードを今使えない
・山札が空の状態でリロードする
・リロードで捨てたカードを即引き直す
```

## 処理

```text
手札カードを1枚選択
↓
リロード実行
↓
選択カードを捨て札へ送る
↓
山札から1枚引く
↓
リロードクールタイム5秒開始
```

山札が空の場合：

```text
選択カードを捨て札へ送る
↓
山札が空なら捨て札をシャッフル
↓
1枚引く
```

この時、今捨てたカードを即引き直す可能性がある。  
MVPでは許容する。

# 7. リロード対象カード

## 論点

どのカードをリロード対象にできるか。

## 選択肢

```text
A. 通常建物カードのみ
B. 政策/偉人以外
C. 全カード
```

## 推奨案

```text
全カードをリロード対象にする。
```

## 理由

政策や偉人が序盤に来て手札を圧迫するケースがある。  
全カード対象にした方が分かりやすく、手札事故を軽減できる。

## 起こりうるシーン

```text
・偉人カードが初手に来たが、コスト不足で使えない
・政策カードを今は使いたくない
・建物カードを探しに行きたい
・手札に不要カードが複数ある
```

## 処理

```text
リロードで捨てたカードは、カード種別に関係なく捨て札へ送る。
リロードは使用扱いではない。
政策/偉人をリロードしても、バトル中除外には送らない。
```

# 8. カード使用後の行き先

## 論点

カード種別ごとに、使用後どこへ行くか。

## 選択肢

```text
A. 全カードを捨て札へ
B. 全カードを除外へ
C. 種別ごとに分ける
```

## 推奨案

```text
通常建物カード：捨て札
政策カード：内部的にバトル中除外
偉人カード：内部的にバトル中除外 + UI上は盤面表示
```

## 理由

通常建物カードは何度も引いて、同種建物を複数建てる設計。  
政策カードは一時的な強効果なので同一バトル中に何度も使わせない。  
偉人カードは盤面に配置されるカードなので、プレイヤー視点では「除外」ではなく「盤面上に偉人がいる」見え方にする。

## 起こりうるシーン

```text
・製材所を使って建設キューに入れる
・政策カードを使う
・偉人カードを使って盤面に配置する
・使用後の政策が山札に戻ってしまうと強すぎる
・偉人カードが除外領域にあるように見えると不自然
・通常建物が除外されると都市が建たない
```

## 処理

```text
通常建物カード：
建設キュー投入時に捨て札へ送る。

政策カード：
効果発動後、内部的にバトル中除外へ送る。
UI上は手札から消えるだけでよい。

偉人カード：
配置先を選択し、盤面に偉人を表示する。
カード自体は内部的にバトル中除外へ送る。
効果はそのバトル中継続する。
```

# 9. 通常建物カードの使用タイミング

## 論点

通常建物カードはいつ手札から離れるか。

## 選択肢

```text
A. 配置先を選んだ瞬間
B. 建設キューに入った瞬間
C. 建設完了時
D. 建設キャンセル時
```

## 推奨案

```text
建設キューに入った瞬間、手札から離れて捨て札へ送る。
```

## 理由

カード使用と建設進行を分離できる。  
建設中ずっとカードが手札に残ると分かりにくい。  
建設キュー側で進捗を管理し、カード領域側はシンプルにする。

## 起こりうるシーン

```text
・製材所カードを使い、建設キューに入る
・建設中に山札が切れて、製材所カードが再度引ける
・同じ建物を複数建てる
・建設キューが詰まっているが、カードはすでに捨て札へ行っている
```

## 処理

```text
建物カード使用
↓
資源確認
↓
配置先確認
↓
建設キュー投入
↓
カードは捨て札へ
```

資源不足/配置不可の場合：

```text
カードは使用不可。
手札に残る。
```

# 10. 政策カード

## 論点

政策カードをどう循環させるか。

## 選択肢

```text
A. 使用後捨て札へ行き、同一バトル中に再利用可能
B. 使用後永久除外
C. 使用後バトル中除外、次バトルで復帰
```

## 推奨案

```text
政策カードは、使用後内部的にバトル中除外へ送る。
次バトル開始時にデッキへ戻る。
UI上は手札から消えるだけでよい。
```

## 理由

政策カードは強い一時効果として扱いたい。  
同一バトル中に何度も使えると強すぎる。  
また、政策を「もう一度使う」というのは直感的にやや不自然。  
一方、ラン中に獲得したカードとしては次戦以降も使いたい。

## 起こりうるシーン

```text
・増税を使って通貨を得る
・徴兵令を使って兵力を増やす
・祝祭を使って幸福度を回復する
・政策を使った後、山札シャッフルしても戻ってこない
・次バトルではまた使える
```

## 処理

```text
政策カード使用
↓
コスト確認
↓
効果発動
↓
カードは手札から消える
↓
内部的にバトル中除外へ
↓
同一バトル中は再ドロー不可
↓
バトル終了時にデッキへ戻る
```

コスト不足の場合：

```text
使用不可。
手札に残る。
```

# 11. 偉人カード

## 論点

偉人カードをどう使い、どう見せるか。

## 選択肢

```text
A. 使用後捨て札へ
B. 使用後バトル中除外としてUIにも表示
C. 配置先を選び、盤面上に偉人として表示する
```

## 推奨案

```text
偉人カードは、配置先を選んだ時点で手札から離れる。
内部的にはバトル中除外へ送る。
UI上は、選択した配置先に偉人が表示される。
```

## 理由

偉人カードは、単なる使い切り効果ではなく、盤面上に存在している感覚がある方が自然。  
「除外領域に行った」と見せるより、「偉人が配置された」と見せる方が分かりやすい。

## 起こりうるシーン

```text
・偉人カードを引く
・コストが足りず使えない
・配置可能パネルが必要
・使用すると盤面に偉人が出る
・使用後、同じバトル中には引けない
・次バトルではまたデッキに戻る
```

## 処理

```text
偉人カード使用
↓
配置可能パネルを選択
↓
必要コスト/条件を確認
↓
偉人を盤面に配置
↓
カード自体は内部的にバトル中除外へ
↓
UI上は配置済み偉人として盤面に表示
↓
そのバトル中、偉人効果が継続
↓
バトル終了時、偉人カードは次バトル用デッキに戻る
```

条件不足の場合：

```text
使用不可。
手札に残る。
```

# 12. 追加ドロー

## 論点

カード効果・建物効果による追加ドローをどう処理するか。

## 選択肢

```text
A. ターンドローとは別処理
B. 通常ドローと同じ処理
C. 手札上限を無視して引く
```

## 推奨案

```text
追加ドローも通常ドローと同じ処理を使う。
手札上限も適用する。
```

## 理由

処理を統一した方が実装しやすい。  
追加ドローだけ手札上限を無視すると、ドロー効果が強くなりすぎる。

## 起こりうるシーン

```text
・リソースを消費して追加ドローする
・宝物即時報酬でカードを1枚引く
・手札が7枚の時に追加ドローしようとする
・山札が空の時に追加ドローする
```

## 処理

```text
追加ドロー要求
↓
手札上限確認
↓
山札確認
↓
山札が空なら捨て札シャッフル
↓
1枚引く
```

手札上限の場合：

```text
ドローしない。
コストも支払わない。
```

# 13. リソース消費ドロー

## 論点

ドローソースをどう設計するか。

## 旧仕様

```text
旧書庫仕様：
通貨1を消費して1枚ドロー
クールタイムあり
```

この旧仕様は削除する。

## 推奨案

```text
リソース15個を消費して1枚ドローできる。
対象リソースの種類は、カード/建物効果側で定義する。
```

## 理由

ドローを通貨だけに結びつけるのではなく、余剰リソースの使い道として扱える。  
建設に使うか、ドローに変換するかの判断が生まれる。

## 起こりうるシーン

```text
・木材が余っているのでドローに変換する
・石材が余っているが、防壁再建にも使いたい
・食料を人口維持に使うか、ドローに使うか迷う
・リソースが15未満でドローできない
・手札上限でドローできない
```

## 処理

```text
ドロー効果を実行
↓
対象リソースが15以上あるか確認
↓
手札上限を確認
↓
ドロー可能なら対象リソースを15消費
↓
1枚ドロー
```

ドローできない場合：

```text
リソースは消費しない。
```

# 14. バトル終了時のカード領域処理

## 論点

バトル終了時、山札・手札・捨て札・除外をどう扱うか。

## 選択肢

```text
A. そのまま次バトルへ持ち越す
B. 手札だけ捨て札へ
C. 全領域を回収して次バトルでシャッフル
```

## 推奨案

```text
バトル終了時に全領域を回収し、次バトル用デッキとして再構成する。
```

## 理由

盤面や資源が毎バトルリセットされる設計なので、カード領域も毎バトルリセットした方が分かりやすい。  
政策/偉人も次バトルで復帰させる必要がある。

## 起こりうるシーン

```text
・手札に未使用カードが残ったまま勝利
・政策カードが内部的にバトル中除外にある
・偉人が盤面上に配置されている
・山札が残っている
・捨て札に通常建物カードがある
・報酬カードを追加する
```

## 処理

```text
バトル終了
↓
手札を回収
↓
山札を回収
↓
捨て札を回収
↓
内部的なバトル中除外を回収
↓
盤面上の偉人表示をクリア
↓
ランデッキに戻す
↓
報酬カードを追加
↓
次バトル開始前にシャッフル
```

# 15. バトル間設計時間と初期手札

## 論点

バトル間60秒の設計時間中に、初期手札を見せるか。

## 選択肢

```text
A. 見せない
B. 初期手札だけ見せる
C. 初期手札を見せてマリガン可能
D. 初期手札を見せてリロード可能
```

## 推奨案

```text
設計時間中に次バトルの初期手札5枚を表示する。
ただし、使用・リロード・マリガンは不可。
```

## 理由

次マップと初期手札を見て開拓方針を考えられる。  
ただし、設計時間中に操作まで許すと処理が複雑になり、バトル開始前から忙しくなる。

## 起こりうるシーン

```text
・次マップで木材が多い
・初期手札に製材所がある
・初期手札に兵舎がないので早期突撃を諦める
・初期手札に偉人があるがコスト不足
・初期手札が弱いがマリガンはできない
```

## 処理

```text
バトル間設計時間開始
↓
ランデッキをシャッフル
↓
初期手札5枚を確定
↓
設計時間中に表示
↓
プレイヤーはマップと手札を見て方針を考える
↓
60秒経過または準備完了でバトル開始
```

## 起こりうるシーン

```text
・初期手札が弱い
・初期手札とマップが噛み合わない
・プレイヤーが引き直したくなる
・ただし、バトル開始後にリロードで対応できる
```

## 処理

```text
設計時間中に初期手札は見える。
ただし入れ替え不可。
バトル開始後にリロード可能。
```

# 17. 最終突撃フェーズ中のカード操作

## 起こりうるシーン

```text
↓
カード使用不可
↓
リロード不可
↓
追加ドロー不可
↓
ターンドロー停止
↓
手札/山札/捨て札/内部除外はそのまま保持

```

# 21. 同名カード・デッキ枚数

## 論点

同じカードを複数枚取れるか。デッキ枚数が増えすぎた時どうするか。

```text
A. 同名カード制限あり
B. 同名カード制限なし
C. デッキ上限あり
D. デッキ圧縮あり
```

## 推奨案

```text

MVPではデッキ圧縮なし。
```


## 処理

```text
同名カード取得可。
報酬で選んだカードはそのままランデッキに追加。
デッキ圧縮・削除はMVPではなし。
```

# 28. 残論点

大きな仕様論点は一旦解消済み。  
残るのは、実装後のプレイテストで調整する数値とUI。

```text
・手札上限7枚が多すぎないか
・リロード5秒が短すぎないか/長すぎないか
・初期手札5枚で初動事故が少ないか
・リソース15消費ドローが重すぎないか/軽すぎないか
・バトル間設計時間で初期手札を見せる情報量が多すぎないか
・山札切れ時に今捨てたカードを即引き直す挙動を許容できるか
・偉人の配置UIが分かりやすいか
```

# 29. 最終方針

通常建物カードは循環する。  
政策カードと偉人カードは、使用するとそのバトル中だけ内部的に除外される。  
ただし、除外領域はUIには表示しない。

政策カードは使用後、手札から消える。  
偉人カードは使用後、盤面上の配置済み偉人として表示される。

リロードは、手札事故を軽減するための基本操作として全カードを対象にする。  
追加ドローは、リソース15個を消費する仕組みに統一する。

カード領域は、山札・手札・捨て札・内部処理用のバトル中除外の4つで十分。  
バトル終了時にすべて回収し、報酬カードを加えて次バトル用デッキを作る。

MVPでは、マリガン・デッキ圧縮・永久除外などは入れず、まずはシンプルで破綻しないカード循環を優先する。
