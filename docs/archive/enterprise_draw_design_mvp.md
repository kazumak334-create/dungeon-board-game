## 2. 並存システムの体験設計

### 2.1 役割分担の核

旗式突撃とドロー＋強制突撃ゲージは「**異なる時間圧をかけるシステム**」として並存する。プレイヤーが感じるべき体験は別物である。

| システム | 体験する感情 | 操作タイミング | 戦術的役割 |
|---------|------------|--------------|----------|
| 旗式突撃（既存） | 「いま行ける！」という**主体的な賭け** | プレイヤーが任意で発動 | ピーク打ち / 戦線ラッシュ / 配分の答え合わせを能動的に作る |
| ドロー＋強制突撃ゲージ（新規） | 「時間が無くなる…」という**受動的な圧** | 10ターン経過で自動発動（早期突撃も可） | 終局を強制 / 引き伸ばし戦術を不可にする / バトル時間を5分に固定 |

### 2.2 なぜ両方必要か

**旗だけだと**：プレイヤーが「永遠に資源を貯める」最適戦略に陥る。バトルが間延びする。

**ゲージだけだと**：「10ターン目を待つだけ」の受動プレイになる。介入の主体性が失われる。

**両方あると**：
- 序中盤：旗を立てて任意のピーク打ちを設計する（主体）
- 終盤：ゲージが赤くなり「いまピーク作れていないなら早期突撃で奇襲するか / 我慢して10ターン目に賭けるか」の決断が生まれる（受動 → 主体への転化）

これが「**設計して、介入を仕込んで、答え合わせを観戦する**」核体験の時間構造になる。

### 2.3 並存時の操作フロー（時系列）

```
バトル開始
↓ ターン1〜3：ドローで資源採取建物・住居を配置（盤面設計）
↓ ターン4〜6：兵舎・書庫を稼働させる（介入仕込み）
↓ ターン7〜9：旗を立てて任意突撃 or 我慢
↓ ターン10：強制突撃ゲージ満タン → 全軍突撃（答え合わせ）
バトル終了
```

旗は「いつでも倒せる」が、突撃ゲージは「いつかは倒れる」。この非対称が緊張を作る。

### 2.3.1 操作フロー図（誰が何をするか）

並存システムでプレイヤー・ゲージ・ユニットがそれぞれ何を担うかを明確化する。

```
[プレイヤー]                [ゲージ/タイマー]               [ユニット]
   │                            │                             │
   │  ① 旗を盤面で立てる       │                             │
   ├──────→ 盤面の旗オブジェクト                              │
   │            ↓                                              │
   │            └──「ここに集合せよ」シグナル ───────────→ 集合・前進
   │                                                          │
   │  ② 早期突撃ボタン押下      │                             │
   ├──────→ HEADER 右の EARLY CHARGE ボタン                   │
   │            ↓                                              │
   │            └──「target_priority 上書き」 ───────────→ 全軍前線制圧モード
   │            └──「旗倒し連鎖発火」 ────────────────────→ 集合・前進（同時）
   │                                                          │
   │                            ③ 強制突撃ゲージ満タン        │
   │                            ↓                              │
   │                            ├──「target_priority 上書き」→ 全軍前線制圧モード
   │                            └──「旗倒し連鎖発火」 ──────→ 集合・前進（同時）
   │                                                          │
   │  ※ ②と③は同じ最終効果。ただし②はプレイヤー任意・③は時間切れ自動
```

### 2.3.2 操作別の動作差マトリクス

| 動作 | 旗倒し単独 | 早期突撃ボタン | 強制突撃ゲージ満タン |
|------|----------|--------------|--------------------|
| 前進フラグ ON（集合・前進） | ✓ | ✓ | ✓ |
| target_priority 上書き（前線制圧） | × | ✓ | ✓ |
| 旗倒しイベント連鎖 | -（本人） | ✓ | ✓ |
| ドロー停止 | × | ✓ | ✓ |
| 建設停止 | × | ✓ | ✓ |
| バトル終局 | × | ✓ | ✓ |

**読み方:**
- 旗倒し単独 = 「集合せよ」だけ。target は変えないので戦闘優先順位は維持される
- 早期突撃 / 強制突撃 = 「集合せよ + 全員突っ込め」。ドローも建設も止まる

**実装上の根拠:** 要件定義書 §4.6.2 / §9.5（target_priority 上書きは強制突撃側のみ）

### 2.4 設計判断基準

並存システムを実装する際、以下を必ず守る。

- 旗倒しと早期突撃ボタンは**別操作**として独立させる（同一ボタンに統合しない）
- 旗倒しは「自陣ユニットの集合・一斉前進」、早期突撃は「全軍 target_priority 上書き＋強制前進」という**動作差**を残す
- ゲージ満タンによる強制突撃は**旗倒しを自動的に伴う**（旗を立て忘れていても全軍が動く）

## 3. 経済サイクルと人口システムの設計

### 3.0 経済サイクル全体像（v0.2 改訂2 新規）

v0.2 ではハーベスター割り当てを廃止し、配置済みの採取建物・生産建物が**自動稼働で資源を生み出す**。プレイヤーの介入は「**何を建てるか・どこに建てるか・いつ突撃するか**」の3点に集約される。

#### 3.0.1 リソースの全体マップ

```

  木材 / 石材             ↑生産              ↑住居供給            ↑（v0.3で具体化）
  硫黄 / 小麦             │                  │                    │
  鉄鉱石 / 綿花           │                  ↓人口×N/秒消費       │
   ↑                      │                                       │
   │ 採取建物             │ 生産施設                              │
   │ 自動稼働             │ （食料生産＝人口消費）                │
   │                      │                                       │
   ↓ 建設コスト           ↓                                       │
[手札カード] ──盤面ドロップ──→ [建物稼働]                        │
                                  │                                │
                                  ├→ 採取建物 → 資源6種            │
                                  ├→ 生産施設 → 食料               │
                                  ├→ 住居 → 人口上限 +N            │
                                  ├→ 書庫 → 資金消費でドロー       │
```

#### 3.0.2 各リソースの役割

| リソース | 生産源 | 消費先 | 用途 |
|---------|--------|--------|------|
| 木材 / 石材 / 硫黄 / 小麦 / 鉄鉱石 / 綿花 | 各採取建物 | 建設コスト | 建物建設 |

| 満足度 | （v0.3 具体化） | （v0.3 具体化） | （v0.3 具体化） |

| 資金（=通貨） | 市場（+1/10秒） | 書庫（1資金=1ドロー / CD5秒） | 追加ドロー |

#### 3.0.3 v0.2 での簡略化

- **満足度**は v0.2 では初期値0のみ・実装は v0.3 へ繰越
- **食料消費**は v0.2 では「人口×N/秒」の N を仮確定（テストプレイ後微調整）
- **兵舎の兵力蓄積レート**も仮確定（テストプレイ後微調整）

### 3.1 「住居」とは何か

これまでの GAME_DESIGN.md には**人口上限**の概念がない（hex_mvp は初期配置式、Econ MVP はハーベスター数のみ）。本企画で**新規概念**として追加する。

| 用語 | 実装名 | 定義 |
|------|-------|------|
| 人口（population） | - | 「建物を稼働させるために必要な労働力」の単位 |
| 人口使用数 | `population_used` | 現在稼働中の建物が占有している人口の合計 |
| 人口上限 | `population_cap` | 同時に稼働可能な建物の合計人口コスト上限 |
| 住居 | `card_house` | 人口上限を増やす建物（人口供給源） |
| 必要人口 | `population_required` | 建物1棟あたりの稼働コスト |
| 供給人口 | `population_supply` | 住居1棟あたりの上限増加量 |

### 3.2 計算式の詳細版

#### 3.2.1 人口上限の計算式（改訂2：拠点効果 +50 を追加）

```
population_cap = 拠点効果(+50) + Σ(住居n.population_supply)
              = 50 + 住居稼働数 × 3
```

| 住居稼働数 | 拠点効果 | population_cap |
|----------|---------|----------------|
| 0棟 | +50 | **50** |
| 1棟 | +50 | 53 |
| 2棟 | +50 | 56 |
| 3棟（全稼働） | +50 | **59** |

**注：** 改訂2で「拠点（BASE）= 人口上限 +50」を追加。これにより**初期人口0でも全採取建物・兵舎・書庫・市場を稼働させる余裕**が生まれ、序盤デッドロックを防ぐ。住居は v0.2 では「上限のさらなる拡張」として機能する。

#### 3.2.2 人口使用数の計算式

```
population_used = Σ(稼働中建物n.population_required)
```

各建物の `population_required`（要件定義書 §11 と一致）:

| 建物 | population_required |
|------|---------------------|
| 資源採取建物（木/石/硫黄/小麦/鉄/綿） | 1 |
| 兵舎（card_barracks） | 2 |
| 書庫（card_library） | 1 |
| 市場（card_market） | 1 |
| 住居（card_house） | 0（自分は要求しない・供給する） |

#### 3.2.3 建物稼働判定

```
稼働可能 ⇔ population_used + 新建物.population_required <= population_cap
```

すでに稼働中の建物が `population_cap` を超過した場合（住居破壊時）：

```
超過分 = population_used - population_cap (> 0)
→ 超過分の建物がランダム停止（§3.5 アルゴリズム参照）
```

#### 3.2.4 住居の役割（改訂2：拠点+50で必要性が変化）

13枚デッキを全部稼働させた場合の人口需要:

```
全稼働必要人口 = 採取6種(6×1) + 兵舎2(2×2) + 書庫(1) + 市場(1)
              = 6 + 4 + 1 + 1
              = 12
```

拠点効果のみの上限:

```
拠点(+50) = 50  ≫ 12
```

**v0.2 では拠点+50 で全建物が余裕で稼働可能。**

このため、住居の v0.2 における役割は以下に再定義する：

- v0.1 の役割：「3人口分の取捨選択を必然化」（廃止）
- v0.2 の役割：**「実際の人口を増やすための上限拡張」**（実人口は v0.3 で具体化）

→ 住居3棟は「将来の人口増加（v0.3）」を見越した先行投資。v0.2 単体での戦術的圧は薄い（テストプレイ後に必要なら供給量再調整）。

#### 3.2.5 供給量の代替案検討（採用：案A）

| 設計案 | 1棟あたり供給 | 3棟合計 | 取捨選択 | 評価 |
|--------|------------|--------|---------|------|
| **案A（採用）** | +3 | 9 | 3人口分の不足が常に発生 | **○** |
| 案B | +2 | 6 | 6人口分不足。書庫・市場が建てられない事故多発 | × きつすぎ |
| 案C | +4 | 12 | ぴったり全部稼働。取捨選択が消える | × KISS違反方向 |

### 3.3 住居の戦術的意義

- 住居を**早く建てる**ほど、後半の建物稼働数が増える
- 住居を**建てずに**戦闘建物を優先すると、序盤に強いが中盤で稼働が止まる
- 住居3枚を**いつドローするか・いつ建てるか**が戦略の軸になる

これは「資源採取 vs 戦闘 vs 経済」の三すくみを補完する**第4の軸（人口）**として機能する。

### 3.4 住居の設計パラメータ

- 住居自体は**戦闘力を持たない**（HP のみ・攻撃なし）
- 住居が破壊されると**人口上限が減る**（既に稼働中の建物がランダムに停止 / §3.5 参照）
- 住居の建設コストは**安め**に設定（資源を住居に流す心理ハードルを下げる）
- 「住居を建てる」行為が**前進感を生む**ように、稼働可能になった建物を視覚的に強調する（§5.4 参照）

仮確定値は §8.2「初期カード仕様一覧」に集約。

### 3.5 住居破壊時の停止アルゴリズム

`population_used` が `population_cap` を超えた場合の停止優先順位（要件定義書 §8.5 で確定）:

1. **必要人口の大きい建物から優先停止**（兵舎優先・人口2 > 採取/書庫/市場・人口1）
2. 同人口なら**最後に建設された建物から停止**（LIFO）
3. seed は使わない（リアルタイム挙動・テスト時は他要素で再現）

例：兵舎×1（人口2稼働中）+ 採取×3（人口3稼働中）+ 書庫×1（人口1稼働中）= 計6人口使用中
- 住居1棟破壊で `population_cap` が 9→6 に：超過なし → 停止なし
- 住居2棟破壊で `population_cap` が 9→3 に：超過3人口
  → ステップ1：兵舎（人口2）を停止 → 残超過 1
  → ステップ2：直近建設の採取建物（人口1）を停止 → 超過解消

**注：** v0.2 は拠点+50 が常駐するため、上記は「v0.3 以降の実人口運用」で意味を持つ。v0.2 単体では拠点効果が大きすぎて停止が起きにくい。

#### 3.6.2 食料30の意味

```
住居建設で人口増えた後 → 食料が30秒〜数分単位で消費される
```

→ **v0.2 では食料0でも即時バトル敗北はしない**（人口がほぼ0のため）。v0.3 で実人口運用が始まれば食料が戦略リソース化する。

|------|-----------|--------------|
| HP | 既存値 | 既存値（変更なし） |

| **人口上限への寄与** | **なし** | **+50（常駐）** |
| 戦闘力 | なし | なし（変更なし） |

**設計意図：**

- 序盤デッドロック防止：住居がドローされる前から建物稼働可

- v0.2 単体では「拠点+50 が大きすぎて住居が無意味」に見えるが、これは v0.3 で実人口運用が入ったときの**事前準備**として正しい設計

### 4.2 ドロー順による戦術分岐の検証

10ターン × 1ドロー/ターン = 最大10枚ドロー（書庫を稼働させればさらに増える）。**13枚中、引けるのは平均10枚**なので「引けないカードが3枚出る」前提でデッキが設計されている。

#### パターンA：兵舎先行（攻撃型）
- ターン1〜3で兵舎×2を引く → 攻撃ユニット早期投入
- 弱点：住居が遅れると兵舎の稼働が一時停止する
- 検証視点：兵舎2枚が常に活きる配置か / 人口不足で建てたのに止まる事故が起きないか

#### パターンB：採取先行（経済型）
- ターン1〜3で資源採取建物を複数引く → 中盤以降の物量で押す
- 弱点：序盤の戦闘で守りきれず BASE が削られる可能性
- 検証視点：資源採取6種のうち**どの組み合わせが引けても**最低限の経済が回るか

#### パターンC：住居先行（基盤型）
- 住居3枚を早期に引いて全建物稼働を狙う
- 弱点：住居3枚が固まって序盤の手札を圧迫する
- 検証視点：住居3枚が連続で来た場合の手札詰まりは許容範囲か（手札MAX5枚）

#### パターンD：書庫＋市場先行（ドローエンジン型）
- 書庫＋市場を早期に引いて通貨経由で追加ドロー → デッキ回転
- 弱点：通貨生成までの空白ターンで戦闘建物が手薄
- 検証視点：書庫が機能し始めるターンが何ターン目になるか / 13枚の小デッキで回転は意味があるか

### 4.3 ドロー保留時のターン進行（重要）

**ターン進行は常に30秒周期で独立して進む。**
ドロー受信は手札上限時に保留されるが、ターンカウントは停止しない。

#### 4.3.1 確定挙動

| 項目 | 仕様 |
|------|------|
| ターン進行 | `battle_elapsed_sec` を delta 累積し、`current_turn = int(elapsed / 30)` で独立算出 |
| ドロー保留 | 手札上限到達時、`pending_draws++` でスタック |
| 保留解決 | 手札 ≤ 4 になった次フレームで `pending_draws` を1つ消化 |
| ドローゲージ | 手札MAX中は100%表示で待機（次タイマーは進めない） |
| 強制突撃ゲージ | ドロー保留に**影響されず進む**（ターン進行に同期） |

#### 4.3.2 具体例（手札MAX時の挙動）

```
ターン1 (t=0〜30秒)
  ↓ プレイヤーがカード5枚ストック・建設しなかった
ターン1終了時（t=30秒）
  ↓ ドロー① 発動 → 手札6枚にできない → pending_draws = 1（保留）
  ↓ draw_gauge_value = 100% で停止表示「MAX (5/5)」
  ↓ current_turn は 1→2 に進む（独立進行）
  ↓ 強制突撃ゲージのセグメント1点灯

ターン2 (t=30〜60秒)
  ↓ プレイヤーが手札のカード1枚を建設 → 手札4枚
  ↓ 次フレーム: pending_draws = 1 を消化 → 手札5枚に戻る・pending_draws = 0
  ↓ draw_gauge_value は 0% にリセット（保留解除）

ターン2終了時（t=60秒）
  ↓ ドロー② 発動 → 手札6枚にできない → pending_draws = 1（再び保留）
  ↓ ※ ターン2の通常ドローと、ターン1の保留解決が別イベントとして発火
```

#### 4.3.3 「ターン進行」と「ドロー」の分離原則

```
[時間軸]──────────────────────→
   ↓ battle_elapsed_sec が常時加算
   ↓ current_turn = int(elapsed / 30) ← ターン番号は独立算出
   ↓
   ↓ ドロー要求発火（30秒ごと）
   ↓   ├ 手札に空きあり → 即ドロー
   ↓   └ 手札MAX → pending_draws++
   ↓
   ↓ 強制突撃ゲージ = current_turn / 10 ← 同じく独立算出
```

**重要:** ドローが保留されてもターンは進む。ターン10の強制突撃発動はドロー保留の有無に関係なく時間で確定する。

**実装根拠:** 要件定義書 §4.3（修正後）／ §16 Q11（満タンで停止／ターンは独立進行）

| 項目 | v0.1（旧） | v0.2（改訂2） |
|------|-----------|--------------|
| 兵舎の役割 | 攻撃ユニットを直接生産（タイマーで盤面に出現） | **兵力プール**：稼働中に「兵力」を蓄積 |
| 兵舎稼働時の効果 | ユニット生産タイマーが進む | `兵力 += N / 秒`（N は仮確定値） |
| ユニット出現タイミング | 兵舎ごとのタイマー満了 | **突撃発動時**に兵力→ユニット変換（1:1） |
| プレイヤーの戦略軸 | 兵舎を何個建てるか | 兵舎を何個建てるか × **いつ突撃するか**（ためる時間と量のトレードオフ） |

#### 4.7.2 兵力→ユニット変換ルール

```
変換タイミング：
  ① 旗倒し（任意突撃）
  ② 早期突撃ボタン押下
  ③ 強制突撃ゲージ満タン（10ターン目自動）

変換式：
  生成ユニット数 = floor(現在兵力 / 1) = 現在兵力（1:1）
  変換後の兵力 = 0（リセット）

変換場所：
  各兵舎セルから現出（複数兵舎があれば各セルから分散出現）
```

#### 4.7.3 具体例

```
ターン1〜5：兵舎×2 建設（兵力蓄積レート +N/秒 × 2基）
ターン5〜9：4ターン × 30秒 = 120秒 蓄積
  → 仮 N=0.2/秒なら：兵力 = 2基 × 0.2 × 120秒 = 48兵力
ターン9：早期突撃ボタン押下
  → 兵力48 → ユニット48体が兵舎セルから現出
  → 兵力リセット（0）
```

```
ターン1〜10：兵舎×1 のみ建設（仮 N=0.2/秒）
  → 兵力 = 1基 × 0.2 × 270秒（建設後の稼働時間）= 54兵力
ターン10：強制突撃発動
  → 兵力54 → ユニット54体出現
```

#### 4.7.4 設計上の意義

- **「ためて、いつ放つか」がプレイヤーの戦略軸**になる
- 早期突撃なら少数で奇襲、ゲージ満タン待ちなら大群で総攻撃
- 旗倒しは「少しずつ兵力を間引く」運用も可能（複数回旗倒しなら都度ユニット化）
- 兵力の可視化は HEADER に常時表示（§5.0 参照）

#### 4.7.5 仮確定値（テストプレイで微調整）

| 項目 | 仮確定値 | 補足 |
|------|---------|------|
| 兵力蓄積レート（1兵舎あたり） | +0.2 / 秒 | 30秒ターンで +6兵力/ターン |
| 兵力→ユニット変換比 | 1:1 | 1兵力 = 1ユニット |
| 兵舎の必要人口 | 2 | v0.1 と同じ |
| 兵舎の建設コスト・HP | 既存仕様継承 | req_economy_mvp.md 準拠 |

### 5.2 各 UI 要素の企画意図（What to feel）

#### 5.2.1 手札 UI

**プレイヤーに感じてほしいこと：**「いま自分が握っている選択肢の重み」

- カードは**小さくしすぎない**（コスト・効果が一目で読めること）
- 5枚並んだとき、**どのカードが一番強いか**ではなく、**どのカードを今切るか**で視線が止まるレイアウト
- ドラッグ開始時のホバー演出は「**設置の気持ちよさ**」を最優先（クリック→設置モードでも可だが、D&D で直接盤面に置ける方が体験が良い）

**避けるべきこと：**
- カード枚数表示の数字を主役にする（「Deck:N」等は補助情報）
- 手札 0 枚状態の空スロットを目立たせる（不安を煽るだけで意味がない）

#### 5.2.2 ドローゲージ

**プレイヤーに感じてほしいこと：**「次の選択肢がもうすぐ来る」という**期待**

- 30秒は長い。**進捗が見えていることが安心感**につながる
- 残り3秒で色が変わる演出は「**もうすぐ何かが起きる**」前兆として機能させる
- 手札 MAX で保留中はゲージをグレー化＋「MAX」表示（**プレイヤーの責任で詰まっている**ことを視覚的に伝える）

**避けるべきこと：**
- ゲージを大きくしすぎる（盤面観戦の邪魔）
- ゲージに装飾を入れすぎる（情報量を増やさない）

#### 5.2.3 強制突撃ゲージ

**プレイヤーに感じてほしいこと：**「**時間が終わる**」という不可逆な圧

- ドローゲージとは**別の場所**に配置する（同じ場所にあると役割が混在する）
- 10分割の段階バーを推奨（ターン進行が**離散的**であることを伝えるため）
- ターン7以降で色が橙→赤に変化し、**焦りを誘発**する
- ターン10では赤＋ブリンク（プレイヤーが「もう来る」と覚悟する瞬間）
- 早期突撃ボタンは**ゲージのすぐ隣**に置く（受動的な圧→主体的な賭けへの転化動線）

**避けるべきこと：**
- ゲージをカウントダウン表示のみにする（数字だけだと感情が動かない）
- 早期突撃ボタンを離れた場所に置く（並存システムの動線が切れる）

#### 5.2.4 書庫 UI（CD 演出）

**プレイヤーに感じてほしいこと：**「**もう1枚**引きたい」という追加介入の選択肢

- CD 中はアイコン上に**円形プログレス**（5秒は短いので視覚進行が必要）
- 通貨不足時はアイコンを薄表示＋ツールチップ（**機能していないことが3秒で分かる**）
- 書庫が複数あるときは、**最も先に CD が明けるもの**を強調表示する（プレイヤーの注意を1点に集める）

**避けるべきこと：**
- CD 中にも押せてしまう（不発操作はストレス）
- CD完了時の演出を派手にしすぎる（書庫はサブシステム）

#### 5.2.5 旗と早期突撃ボタンの位置関係

**プレイヤーに感じてほしいこと：**「これは**自分の意志**で倒すもの」

- 旗倒しは**盤面上の旗オブジェクト**を直接クリック（既存仕様）
- 早期突撃ボタンは**強制突撃ゲージの右隣**（HUD 上）
- この2つは**操作場所が違う**ことで、機能の違いが直感的に伝わる

**避けるべきこと：**
- 「突撃」系のボタンを1箇所に集約する（並存の意義が消える）

#### 5.2.6 人口表示

**プレイヤーに感じてほしいこと：**「**もう建てられない**」という上限の存在

- 現在人口 / 上限を「**N / M**」形式で表示（手札周辺に配置）
- 上限到達時は赤色 + 警告アイコン
- 建物カードをドラッグした際、人口不足なら**カードに「人口不足」オーバーレイ**を表示（盤面に置く前に分かる）

**避けるべきこと：**
- 人口を別画面に隠す（戦況と直結する情報）
- 警告を音だけで出す（視覚優先）

#### 5.3.4 手札詰まり時のUI仕様（重要）

「手札MAX中もターンは進む」を視覚的に明示する：

- 手札スロットには変化なし（5枚並んだまま）
- ドローゲージのみ「**MAX (5/5)**」赤表示でグレーバー
- 強制突撃ゲージは**通常通り進行**（ターン進行は止まらない）
- 「ドロー保留中ですよ・カード使ってね」のメッセージは出さない（プレイヤーの責任で詰まっていることを暗黙に伝える）

| ターン10 | 「来た」の瞬間 | ゲージ赤＋ブリンク → 全軍前進アニメーション |

### 5.5 住居稼働時の演出（重要）

住居を建てて人口上限が増えたとき、**それまで人口不足で停止していた建物が稼働開始する**。この瞬間に明示的な視覚フィードバックを入れる。

- 停止中の建物：薄表示＋「人口不足」アイコン
- 住居建設完了 → 稼働開始：**点灯エフェクト**＋稼働音
- これにより「**住居を建てる行為が前進感**」を作る
